# 计划 057：托盘窗口截图与安全候选快照

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/057_window_capture.md`

## 目标

交付从 tray 发起的窗口截图：菜单只展示捕获后端在当前会话可验证的非 Pinora 候选窗口，点击后重新验证目标并取得真实窗口像素，再进入既有标注 Overlay。整个流程不得创建控制窗口、候选选择窗口或任务栏/Dock 条目；目标消失、最小化、权限拒绝或后端不支持时保持 tray 常驻并返回受控失败。

## 非目标

- 不实现跨平台原生窗口选择高亮、全局鼠标点选、窗口录制、滚动长截图、窗口阴影/透明边界自定义或延时窗口截图。
- 不改变区域、全屏、显示器指定、延时截图、历史、OCR、贴图数据模型或默认热键。
- 不将 xcap 的编译、fake 候选或 GitHub runner 结果描述为原生窗口捕获、任务栏/Dock 或权限行为已验证。

## 依赖关系

- 复用 `CaptureProvider`、`CaptureImage`、tray 动作、`desktop_shell` 冷捕获编排和 `window_policy`。
- `xcap 0.9.7` 已暴露 `Window::all`、窗口标识、标题、几何、最小化状态及 `capture_image`；该能力需以本地目标与平台后端实际返回为准。
- 054 的辅助窗口工厂和 056 的 tray-only 自隐藏恢复不可回退。

## 约束

- 窗口候选 ID 是后端内部标识，不写入 UI 标签、日志、历史或错误详情；菜单标签仅使用经过清洗、截断的应用名与标题。
- Pinora 自己的 Overlay、贴图、设置、历史和隐藏 display-handle 必须从候选中排除；目标在点击后重新枚举并按不可变 ID、几何和显示器上下文验证，禁止回退到别的窗口。
- 后端只支持显示器截图时窗口菜单不可用或返回明确能力受限，绝不把全屏或区域图像伪装成窗口截图。
- 所有捕获完成路径继续由 `window_policy` 创建 Overlay；不新建候选选择窗口，不在任务栏/Dock 引入新入口。

## 检查点

- core 的窗口目标只作为后端内的快照身份使用，不能由通用显示器路径解析或持久化。
- tray 仅展示经清洗的有限候选；点击后只允许同一已重验目标进入冷捕获。
- 捕获 worker、缓冲或 Overlay 失败时窗口路径回到 tray，而不会退出事件循环或创建控制窗口。

## 计划级风险

- xcap 的候选列表与菜单之间存在正常的时间窗口；二次验证只能安全拒绝，不能保证用户选中的窗口仍然存在。
- 一些平台会拒绝窗口枚举或取像；后端必须隐藏该能力或回 tray，不能改用显示器截图。
- 静态窗口策略只表达任务栏/Dock 请求，真实合成器是否遵守仍依赖原生桌面验证。

## 阶段

1. 在 core 定义窗口候选快照、目标身份与受控错误契约，并为 fake/后端路由建立离线测试。
2. 为 xcap 接入候选枚举、清洗过滤、重新验证与真实窗口像素转换；不能支持的后端明确拒绝。
3. 在 tray 与 desktop shell 建立目标菜单、冷捕获、现有 Overlay 交接和失败回 tray；执行质量门禁与三平台 CI。

## 完成标准

- tray 可对可用后端展示安全窗口候选并捕获选中窗口；Pinora 自身窗口、失效目标和不支持后端不会被错误捕获或回退。
- 成功只交接真实窗口像素至既有 Overlay；任意失败保持 tray 常驻且不创建额外任务栏/Dock 窗口。
- 定向契约测试、workspace 严格门禁、`ctx validate` 和本次 GitHub Linux/macOS/Windows CI 通过；真实桌面验证缺口如实记录。

## 风险

- xcap 在 Wayland、权限隔离或窗口最小化时可能不能列举或返回内容；只能报告能力受限，不能用屏幕截图替代。
- 菜单在创建后可能过期；点击时必须复验，避免错误捕获同位置或同标题的另一个窗口。
- 标题可能含敏感内容；只在本机 tray 中显示受限长度文本，避免写入日志、历史或测试固定数据。
