# 计划 070：标注选择与删除事务

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/070_annotation_selection_delete.md`

## 目标

落实设计文档 4.4 和 6.2 中 P0 的“选择”工具最小闭环：在当前 Overlay 点击命中最上层已提交标注，显示不写入导出图像的选中轮廓，并允许以 Delete/Backspace 将其作为一个可撤销/重做事务删除。命中、选择和删除必须保持图像物理像素坐标、revision/资产 generation、预览缓存与原图不可变契约；不得打破 Pinora 仅由 tray 常驻且辅助窗口不进入任务栏/Dock/分页器的约束。

## 非目标

- 不实现对象拖动、缩放、旋转、样式修改、框选多选、图层排序、跨文档复制粘贴或标注持久化。
- 不改截图、贴图、OCR、导出、历史、窗口工厂、系统菜单、平台适配器或后台任务。

## 约束

- 选择只引用当前 `AnnotationDoc` 的索引；文档发生提交、撤销、重做、清空、重选或取消时必须失效选择，不能复用陈旧索引。
- 命中以最上层为准，至少覆盖图形描边/填充、线/箭头/画笔、序号、文本和马赛克/模糊区域；选择轮廓只在 Overlay 呈现层绘制，不能进入 `AnnotationDoc`、导出、贴图或 OCR 输入。
- 删除必须是内存事务：保留原索引和对象，一次 undo 原位恢复，一次 redo 再次删除；无选中对象时 Delete/Backspace 无副作用且不推进 revision。
- 所有操作只作用于现有 Overlay，不创建窗口、事件循环、系统菜单、截图或 worker；Overlay、贴图、历史和设置仍只能经 `window_policy` 隐藏创建并展示，Pinora 空闲时只存活于 tray。

## 依赖关系

- 依赖 030/032/069 的单调 revision、redo 分支和清空事务。
- 依赖 068 的提交层缓存与草稿等价契约。
- 依赖 061/066 的 tray-only GUI 会话、辅助窗口唯一工厂与展示入口。

## 阶段

1. 在核心文档中补齐顶层命中和按索引删除事务，锁定复杂标注的命中、绘制顺序与 undo/redo。
2. 接入 Overlay 选择工具、工具栏入口、选中轮廓和 Delete/Backspace；所有文档变更都会清除选择。
3. 覆盖缓存/资产失效、工具栏、键盘和窗口策略回归，执行全量离线门禁并更新稳定事实与风险。

## 检查点

1. 重叠对象点击选择最上层；未命中不改变文档或 revision，选中轮廓不会导出。
2. 删除/undo/redo 精确保留绘制顺序、对象内容和 revision 单调性；后续新增清除 redo 分支。
3. 操作期间不产生新窗口、任务栏/Dock/分页器入口、系统菜单、截图或后台任务，窗口策略递归守卫继续通过。

## 计划级风险

- 复杂几何的命中容差可能与最终视觉边缘不完全一致；需要以像素坐标、最上层优先和各标注类型回归锁定，真实 HiDPI 点击仍待原生会话验证。
- 选择高亮如果错误写入提交图层会污染导出或缓存；必须把高亮放在 Overlay chrome，并以像素比较证明它不改变合成结果。
- 静态建窗守卫不能证明真实窗口管理器最终状态；Windows、macOS、X11、KDE Wayland 的 tray、任务栏/Dock、分页器、首帧和焦点仍需实机验收。
