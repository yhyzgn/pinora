# 计划 072：Overlay 选区边角调整

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/072_selection_resize_handles.md`

## 目标

落实设计文档 4.2 与 6.1 的 P0 区域选择交互：在已有选区的四角和四边提供可见命中热区，用户可拖动任一热区调整相应边界，选区始终留在当前捕获画布并满足最小尺寸。操作只能在既有 Overlay 内完成，Pinora 空闲仍只驻留系统 tray，任何辅助层均不得成为任务栏、Dock 或分页器项。

## 非目标

- 不实现选区旋转、移动以外的新手势、比例锁定、磁吸、跨显示器选区、标注对象缩放、文本框调整或贴图窗口缩放改造。
- 不改变截图后端、资产格式、标注坐标/事务、导出、OCR、贴图、历史、系统菜单、窗口工厂或后台任务。

## 约束

- 八个调整热区和边界调整规则必须位于 `pinora-core` 的纯选择模型；Overlay 只负责命中、光标输入与绘制，不能自行重写几何规则。
- 任何边/角拖动都必须把坐标 clamp 到当前 `SelectionSession` bounds，且绝不突破 `min_edge`；跨过对边时停在最小尺寸，不翻转已确认选区。
- 仅当当前选区没有已提交或草稿标注时开放边角调整，避免在未声明的坐标转换中丢失标注或错误复用资产。已有标注时继续使用既有重选路径。
- 不创建窗口、事件循环、系统菜单、截图或 worker；Overlay、贴图、历史和设置继续只经 `window_policy` 隐藏创建与唯一展示入口。

## 依赖关系

- 依赖 009 的 `SelectionSession`、最小边长和物理像素坐标。
- 依赖 061/066 的 tray-only GUI 会话与辅助窗口边界。
- 依赖 071 的现有 Overlay 输入节流、缓存和瞬态编辑生命周期。

## 阶段

1. 将八个调整方向、边界 clamp 和最小尺寸规则收敛到核心选择模型，并以纯逻辑测试锁定。
2. 在既有 Overlay 绘制边角热区、命中并接入拖动状态；保证拖动预览和松手后的选区一致。
3. 覆盖已有标注的保护行为、键盘移动回归、窗口策略与全量离线质量门禁，更新上下文事实和风险。

## 检查点

1. 四边和四角可独立调整，边界、最小尺寸、反向拖动和极限坐标均稳定。
2. 选区调整只发生在既有 Overlay 内；不产生标注事务、截图、导出、OCR、贴图或后台任务。
3. 源码窗口守卫继续通过，空闲仅有 tray；真实任务栏/Dock/分页器风险明确保留。

## 计划级风险

- 八方向端点计算错误可能造成一像素偏差、选区反转或小于最小尺寸；必须让 core 模型成为唯一规则源并覆盖边界值。
- 调整时若丢弃已提交标注或错误更新资产，会破坏导出和撤销语义；必须在有标注/草稿时禁用该入口。
- 静态守卫不能观察真实窗口管理器或 4K/HiDPI 连续拖动帧时间；不得把离线测试当作任务栏/Dock 或性能结论。

## 完成标准

- 用户可在未标注的当前 Overlay 选区拖动四边或四角精确调整，预览、确认和像素坐标一致。
- 核心选择规则、Overlay 输入、键盘既有行为和资产/标注保护均有回归测试。
- 定向测试、fmt、workspace check、严格 Clippy、全量离线测试、差异检查和 `ctx validate` 通过；真实桌面、HiDPI、帧时间和 tray/任务栏/Dock/分页器风险明确保留。

## 完成记录

- `pinora-core::selection` 已增加 `SelectionHandle` 的八方向模型、热区中心和 `resize_from_handle`；核心在单点中处理 bounds、最小边长、反向拖动和不翻转选区。
- Overlay 在没有草稿或已提交标注的 Ready 选区中绘制八个边角热区，命中按最近中心决定；拖动时更新纯内存选区并复用既有 2 像素/32ms 重绘节流，释放或快捷完成时才更新当前源选区与资产身份。
- 有草稿或已提交标注时不会进入选区调整，保持既有重选行为，避免隐式丢失标注或错误复用导出/OCR/贴图输入；实现没有增加窗口、事件循环、系统菜单、截图或 worker。

- 未验证：真实 Windows、macOS、X11、KDE Wayland 的热区可读性、1x/2x DPI 命中、连续拖动帧时间、焦点，以及辅助窗口绝不进入任务栏、Dock 或分页器的窗口管理器行为。
