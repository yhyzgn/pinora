# 计划 055：托盘逐显示器全屏捕获与目标绑定缓存

- 状态：进行中
- 负责人：Codex
- 当前任务：`.context/tasks/055_display_targeted_capture.md`

## 目标

将捕获后端已有的 `DisplayId` 能力暴露为托盘中的逐显示器全屏截图入口，并让桌面壳把该目标贯穿到冷捕获与预截帧消费。用户选择某个显示器后，不得错误复用另一台显示器的缓存帧；目标在捕获前不可用时返回受控失败。

## 非目标

- 不实现跨显示器拼接、窗口捕获、延迟倒计时、显示器热插拔订阅、原生显示器选择面板或默认目标持久化。
- 不改变 F2/F3、IPC、历史、贴图、OCR、窗口策略或托盘唯一常驻语义。
- 不将托盘菜单、离线 fake、CI 或单显示器环境表述为真实双屏/HiDPI/热插拔验收。

## 依赖关系

- 复用 `CaptureProvider::displays`、`CaptureRequest::FullDisplay`、`DisplayInfo` 与 `FrameCache`，不新增依赖或外部服务。
- 依赖 054 的托盘唯一常驻与辅助窗口策略；本任务不新建常驻窗口。

## 约束

- 托盘菜单在创建时仅展示当前探测到的显示器，并把菜单 ID 映射为不可变 `DisplayId`；枚举失败时保留默认截图动作，不伪造显示器项目。
- 指定显示器捕获必须在实际调用后端前重新核验当前拓扑仍存在目标 ID；已失效目标只能报告 `NotFound`/受控失败，不能悄悄改拍其他屏幕。
- 默认 F2/F3 可继续复用预截帧；指定显示器只接受 display ID、物理 origin、尺寸与 scale 全部一致的缓存帧，否则走该目标的受监督冷捕获。
- 贴图、Overlay、历史和设置仍使用 054 的 `window_policy`，任务栏/Dock 行为不得回退。

## 检查点

- 单显示器时保留当前托盘动作；多显示器时每个目标都有独立全屏截图动作。
- 指定目标命中同目标预截帧时立即打开完整选区 Overlay；不匹配或失效时拒绝旧帧并仅请求该目标。
- 默认最大面积目标、全屏初始选区、取消、错误恢复和帧缓存暂停/恢复语义保持兼容。

## 计划级风险

- 托盘显示器列表仅在进程启动时建立；热插拔后的旧菜单项必须受捕获前核验保护，但不会自动刷新菜单。
- 指定非默认屏幕通常没有预热帧，首次点击可能走冷捕获；不能将其误报为 Snipaste 级零延迟。
- 真实桌面坐标、缩放和任务栏行为仍需要多平台原生会话测试。

## 阶段

1. 扩展托盘动作为带 `DisplayId` 的安全菜单映射，并锁定单/多显示器离线契约。
2. 在 desktop shell 建立目标捕获意图，核验拓扑并限制 FrameCache 消费。
3. 运行定向、workspace、上下文和三平台 CI 门禁，记录真实多显示器缺口。

## 完成标准

- 托盘能提供基于当前显示器列表的逐显示器全屏截图动作，目标 ID 不可伪造或错配。
- desktop shell 只将精确匹配的预截帧用于对应目标，失效目标不回退到别的屏幕。
- 定向测试、workspace 严格门禁、`ctx validate` 与 GitHub 三平台 CI 通过；真实多显示器和 HiDPI 验收缺口如实记录。
