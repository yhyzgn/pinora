# 计划 062：标注取色与自适应工具栏

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/062_annotation_color_picker.md`

## 目标

为当前 Overlay 选区提供零重捕获、零新窗口的像素取色：用户选择取色器后点击截图像素，即刻把该 RGBA 颜色设为后续标注颜色并复制 `#RRGGBB`；同时让工具栏在窄选区中换行布局，保证取色入口不因新增按钮溢出或遮挡。

## 非目标

- 不实现屏幕全局取色、贴图窗口取色、系统级放大镜、调色板历史、透明度编辑、RGB 文本格式切换或文件持久化。
- 不重做现有标注渲染、OCR、导出、窗口策略或剪贴板后端。

## 约束

- 只从当前选区映射出的不可变原始截图像素采样；不得为取色重新截图、同步编码整图、烧录标注或阻塞事件循环。
- 取色器必须在现有 Overlay 客户区与现有工具栏内实现，禁止创建系统菜单、提示窗口或任务栏/Dock 项。
- 剪贴板仍经 `ExportJobService`，并绑定当前 Overlay 会话和 `AssetRef`；关闭、重选或 generation 变化后不得交付陈旧结果。
- 工具栏按钮有稳定尺寸，但列数必须由可用画布宽度决定，布局与命中测试不得越过画布边界。

## 依赖关系

- 依赖 030 的标注 revision/资产 generation 契约与 026/027 的受监督剪贴板导出。
- 依赖 054/061 的统一辅助窗口边界；本任务不得新增任何窗口路径。
- 依赖 060 的客户区绘制基线与 053 的渲染缓存经验，避免在鼠标移动中进行整图工作。

## 阶段

1. 在核心标注会话中补充取色工具、显式颜色设置和可测试的像素/HEX 转换逻辑。
2. 将 Overlay 点击映射到选区原始像素，取色后恢复先前绘图工具并通过受监督任务复制颜色文本。
3. 让工具栏换行并显示当前颜色色块；补充窄画布、取色、会话/资产门禁及严格质量验证。

## 检查点

1. 取色坐标严格位于选区和图像范围，RGBA 与 HEX 输出可由纯测试复现。
2. 取色不改变标注文档 revision，不产生草稿、不触发图像烘焙；后续标注才使用新颜色。
3. 窄画布下每个按钮仍位于工具栏边界内且可命中；所有 UI 操作继续使用同一 Overlay 窗口。

## 计划级风险

- 取色显示的是不可变原始截图，不包括尚未导出的标注叠加；这是避免点击时整图渲染和语义歧义的有意边界。
- 系统剪贴板的真实成功仍依赖平台后端，离线测试只能验证任务归属和生命周期。
- 自绘工具栏仍缺少真实 HiDPI、键盘导航、读屏和主题探针，不把静态布局测试外推为原生无障碍支持。

## 完成标准

- Overlay 工具栏可进入取色器，点击有效选区后更新当前标注颜色并通过受监督任务复制 `#RRGGBB`。
- 取色过程不创建窗口、不重新截图、不变更标注文档或资产 generation，关闭/重选时陈旧剪贴板任务被拒绝。
- 工具栏在可用画布不足一行时正确换行，所有按钮与色块保持在画布内。
- 定向测试、fmt、workspace check、严格 Clippy、全量离线测试、diff 检查和 `ctx validate` 通过；真实剪贴板/HiDPI 缺口如实记录。
