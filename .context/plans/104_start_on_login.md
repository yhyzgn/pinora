# 计划 104：用户级开机自启

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/104_start_on_login.md`

## 目标

实现设计文档 4.1/7 的用户显式开机自启设置：启用后 Pinora 在用户登录时以现有 tray-only 入口启动；禁用后只移除 Pinora 自己创建的用户级注册项。设置值只有在平台注册与本地原子保存均成功后才生效。

## 非目标

- 不写入机器级启动项、系统服务、计划任务、登录脚本或任何其他应用的注册项。
- 不新增主窗口、控制窗口、常驻任务栏/Dock/分页器入口或启动时自动截图。
- 不把交叉编译、CI 或离线文件测试称为真实登录会话验收；不实现自动更新、云同步或 P2 生态功能。

## 约束

- 启用/禁用只响应用户在设置面板中的明确保存动作；默认关闭。
- 注册项必须由 Pinora 以稳定所有权标记创建；禁用遇到非 Pinora 所有项必须拒绝，不能删除未知内容。
- 失败时保持 runtime/settings 旧值；若平台注册已改变但设置原子保存失败，尝试补偿回滚并记录受控错误。
- 启动命令只传当前可执行文件的一个参数向量，不经 shell 解析；启动后的空闲生命周期继续仅有 tray、热键、IPC 与帧缓存。
- 平台细节以官方规范和实际支持能力为准；不可用平台必须返回稳定受控失败，不伪造已启用状态。

## 依赖关系

- 依赖 `AppSettings`、原子 `SettingsStore`、`SettingsPanel` 和 `DesktopApp::save_settings` 的既有保存生命周期。
- 依赖 `window_policy` 的 tray-only 窗口隔离以及根入口的单实例 IPC 转发语义。
- 依赖 XDG Autostart、Windows 当前用户 Run 和 macOS 用户级 LaunchAgent 的平台规范；macOS 13+ 的 `SMAppService` 作为后续原生受管路径评估项。

## 检查点

1. v1-v8 设置迁移后自启动稳定为关闭，v9 原子往返保留值。
2. 平台项只处理 Pinora 所有权标记，未知项拒绝覆盖或删除。
3. 平台写入、设置保存和热键重绑的失败不会提交新 runtime 设置，且会尝试补偿恢复旧启动项。
4. 登录启动使用 `--pinora-autostart`，已有实例不转发 `CAPTURE`。

## 平台范围

| 平台 | 用户级机制 | 失败策略 |
| --- | --- | --- |
| Linux | XDG Autostart 的 Pinora 托管 `.desktop` 项 | 无法写入或内容所有权不匹配时拒绝保存 |
| Windows | 当前用户登录启动注册项 | 注册失败或所有权冲突时拒绝保存 |
| macOS | 当前用户 LaunchAgent | 注册/加载失败或所有权冲突时拒绝保存 |
