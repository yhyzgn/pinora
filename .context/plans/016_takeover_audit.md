# 计划 016：Pinora 生产级接管审计与架构重建

- 状态：已完成
- 负责人：未分配
- 当前任务：`.context/tasks/016_takeover_audit.md`

## 目标

在继承已有功能的前提下，完成一次证据驱动的生产级接管：识别 Demo 级实现和技术方案缺陷，冻结可保留的领域行为，重建平台、窗口、任务与 UI 编排边界，并以可验证质量门禁推进重写。

## 非目标

- 不承诺保留 Grok 的现有模块或提交历史。
- 不在没有回归场景和边界设计的情况下继续向 `desktop_shell.rs` 添加功能。
- 不把 Linux/KDE 现状描述为 Windows、macOS 或 Wayland 全面支持。
- 不为了通过编译引入 warning suppression、假平台实现或静态 fake 作为生产能力。

## 约束

- 先保护现有用户可观察行为，再逐能力迁移；每个迁移任务必须可回滚。
- `pinora-core` 保持纯领域层，不依赖 UI、平台 SDK、外部命令或真实桌面。
- 平台能力通过 trait/adapter 注入；外部进程必须拥有超时、取消、退出码和输出大小边界。
- 不连接共享数据库、缓存、消息队列或第三方服务；桌面权限只在明确授权的隔离探针中验证。
- 修复根因，不使用 `#[allow]`、`#[expect]` 或其他 lint 降级掩盖问题。

## 依赖关系

- 依赖现有 `001`–`015` 任务产生的源码、测试和运行证据。
- 先完成本接管审计和架构决策，再进入生产重写任务。
- 后续实现任务依赖本计划明确的模块边界、质量门禁和平台声明。

## 阶段

1. **接管审计**：确认构建、测试、target、运行时、依赖、事件流和外部副作用。
2. **行为冻结**：为区域截图、贴图、标注、OCR、导出和单实例建立可观察回归场景。
3. **架构重建**：拆分平台服务、任务管理、应用状态机、窗口控制器和渲染职责。
4. **质量基线**：恢复 fmt/Clippy 门禁，清理 panic/不受控子进程，补齐 fake 契约和生命周期测试。
5. **能力迁移**：按垂直切片迁移截图、Overlay、贴图、标注、OCR 和导出；每片完成后再移除旧路径。
6. **平台验证**：只对实际验证的 target 和桌面环境声明支持，记录降级矩阵和发布阻塞项。

## 检查点

- 审计报告必须区分已验证事实、推断和未知项。
- 任何删除/重写旧模块前，必须有新路径的等价行为测试和回滚点。
- 每个功能切片完成 `cargo fmt --check`、`cargo check --workspace`、Clippy、定向测试和可运行探针。
- 跨平台声明必须有对应 target 编译和平台探针证据。

## 计划级风险

- 重写可能导致短期功能回退；通过旧路径保留、场景清单和分阶段切换控制。
- 现有 UI 行为没有自动端到端覆盖；先把核心行为下沉到可测试状态机，减少依赖人工记忆。
- 依赖选择可能需要外部官方文档验证；在锁定版本或平台 API 前单独记录研究证据。

## 完成标准

- 已有实现按“保留、迁移、重做、废弃”分类，并且每项有文件和测试证据。
- 新架构不再由单个桌面壳承载所有业务与平台逻辑。
- 默认 Linux 实验能力与正式跨平台能力分层声明。
- fmt/Clippy/测试门禁可重复执行，未知平台和跳过测试明确登记。
- 所有生产重写任务均可单独验证、回滚和交接。
