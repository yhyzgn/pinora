# 计划 087：辅助面板主题渲染

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/087_auxiliary_panel_theme.md`

## 目标

使已经持久化的 `ThemeMode::{System,Light,Dark}` 真正影响设置、历史和诊断三个辅助面板的自绘调色板，并在系统主题变化或设置保存后同步刷新已打开面板。

## 非目标

- 不重绘 Overlay、贴图窗口、贴图右键菜单、tray 原生菜单或系统标题栏；它们各自涉及截图对比度、平台窗口和原生控件，需要独立任务。
- 不引入 UI 框架、字体、主题依赖、系统偏好写入、设置 schema 变更、窗口、事件循环、线程、进程或网络。
- 不把 Linux/Windows/macOS 的 `WindowEvent::ThemeChanged` 编译通过宣称为真实系统主题事件已经验收。

## 依赖关系

- 依赖 v3 `AppSettings.theme`、设置窗口的草稿交互和已有 `Panel` 窗口适配器。
- 依赖 winit 既有 `Window::theme` 与 `WindowEvent::ThemeChanged`，仅将其映射为内部二值系统外观；未知系统外观稳定回退为深色。

## 约束

- 共享主题模块只定义无状态颜色 token 和 `ThemeMode` 解析，不读取环境变量、路径或用户内容。
- `Light`/`Dark` 必须覆盖系统外观；`System` 只在明确收到 Light/Dark 时跟随，未知时默认 Dark，避免不确定的亮色闪烁。
- 设置窗口的主题草稿切换必须立即预览；保存成功才传播到已打开的历史和诊断面板，保存失败保留当前运行时主题。
- 所有现有窗口仍经 `window_policy` 创建与显示；本任务不得改变 tray-only、截图、贴图、热键、OCR、历史数据或 IPC。

## 阶段

1. 建立纯 `PanelTheme`/颜色 token、系统外观映射与离线解析测试。
2. 让设置、历史和诊断面板绘制使用同一调色板；设置草稿即时刷新。
3. 在窗口适配器记录当前系统外观，处理 `ThemeChanged`，并由 DesktopApp 在成功保存时同步打开面板。
4. 覆盖浅/深像素差异、草稿/保存/失败传播和窗口策略回归，执行质量门禁。

## 检查点

1. `Light`/`Dark` 解析不受系统外观影响；`System` 的未知状态稳定映射为 Dark。
2. 三个面板的背景、表面、描边、主要/次要文本、状态和操作按钮均使用主题 token，浅色帧不再与深色帧相同。
3. 设置内切换主题即时改变设置面板；成功保存改变已打开历史/诊断，失败不改变它们。
4. 不创建新窗口或事件循环，任务栏/Dock/分页器策略与 tray-only 守卫保持不变。

## 计划级风险

- 纯 XRGB 帧测试不能验证真实主题切换事件、原生标题栏、tray、读屏、HiDPI 或色彩管理。
- 仅覆盖辅助面板，Overlay/贴图依然是固定视觉风格；交付必须明确此范围，避免误称全应用主题完成。
