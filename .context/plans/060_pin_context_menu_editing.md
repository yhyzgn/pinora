# 计划 060：贴图上下文菜单与原位编辑

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/060_pin_context_menu_editing.md`

## 目标

把贴图的高频操作收敛到同一贴图窗口内的右键上下文菜单，并让“编辑”可回到标注 Overlay 后原位更新既有 `PinId`。菜单、编辑、复制、保存或失败恢复不得新建系统窗口、任务栏/Dock 项或孤立贴图。

## 非目标

- 不实现原生系统菜单、文件选择器、点击穿透、关闭撤销、贴图排序、标题/无障碍适配或跨平台窗口能力探针。
- 不改变已有截图捕获、历史数据格式、OCR 引擎、全局热键或窗口创建工厂。

## 约束

- 右键菜单必须在当前贴图客户区内渲染和命中，不能创建独立 `winit::Window` 或弹出会进入任务栏/Dock 的平台菜单。
- 菜单含复制、OCR、编辑、锁定/解锁、透明度、置顶/取消置顶、另存为和关闭；锁定贴图仍可打开菜单、复制、OCR 与关闭，受限项目不应静默改写状态。
- 编辑提交必须保持同一 `PinId`，原子替换领域图片引用，并使旧 OCR/导出结果失效；取消或任一失败都恢复原贴图可见性和内容。
- 所有新 Overlay 继续经 `window_policy::create_auxiliary_window`；编辑 Overlay 关闭或失败后进程仍回到 tray/贴图正常态。

## 阶段

1. 为 `AppState` 与命令分发添加贴图图像替换、锁定与置顶的可测试事务。
2. 建立可离线测试的贴图菜单布局、命中与渲染模型，接入同一贴图窗口鼠标事件。
3. 将菜单编辑接入既有 Overlay，提交时替换图片并推进资产 generation，取消时恢复原贴图；执行严格门禁和 CI。

## 依赖关系

- 依赖 053 的贴图基础帧缓存与 054 的辅助窗口工厂，避免菜单重绘和编辑 Overlay 重新引入窗口或像素复制路径。
- 依赖 058 的失败回到 tray 状态机，使编辑创建失败、裁剪失败和重新截图不会遗留隐藏贴图。
- 依赖既有 OCR/导出任务监督器，以 `JobOwner::Pin` 和 `AssetRef` generation 拒绝编辑前的陈旧结果。

## 检查点

1. 领域替换、锁定与置顶命令保持 `PinId`、事件和图像引用的一致性。
2. 右键菜单只在现有贴图客户区绘制和命中，不调用平台菜单或创建额外 `Window`。
3. 编辑 Overlay 经 `window_policy` 创建，提交或取消后恢复贴图生命周期；离线门禁通过且真实桌面缺口已登记。

## 计划级风险

- 任务栏/Dock 跳过策略只能由各平台窗口管理器最终确认；离线测试和 CI 不构成真实桌面证据。
- 小贴图、高 DPI、输入法、键盘导航和读屏尚未由原生桌面探针验证；本计划不把自绘菜单声明为原生控件。
- 置顶状态表示应用已向窗口系统请求的层级，不能表示合成器已经接受或维持该请求。

## 完成标准

- 右键在贴图内打开操作菜单，所有规定动作都有真实实现或明确受限状态，且没有额外窗口构造路径。
- 编辑提交保留 `PinId`，关闭旧 owner 任务、推进 `AssetRef` generation、更新像素/尺寸；取消和失败恢复旧贴图。
- 定向测试、workspace 严格门禁、`ctx validate` 与 GitHub 三平台 CI 通过；真实桌面右键、任务栏/Dock、置顶和输入延迟缺口如实记录。

## 风险

- 自绘菜单在高 DPI、键盘导航、读屏和原生主题上仍不等同平台菜单，需后续 UI Adapter 任务。
- `winit` 置顶请求可能被合成器限制；状态只能表示已请求，不能伪造平台实际确认。
- 编辑 Overlay 与贴图可见性/后台任务存在竞态，必须以 owner 关闭和资产 generation 阻止陈旧结果。
