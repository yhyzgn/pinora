# 计划 002：细化 Pinora 功能与架构设计文档

- 状态：已完成
- 负责人：未分配
- 当前任务：`.context/tasks/002_design_document.md`

## 目标

把现有产品初稿提升为可评审、可拆分为开发任务的设计基线：明确功能边界、用户可观察行为、模块责任、状态转换、跨平台降级和关键流程。

## 非目标

- 不实现 Rust 生产代码，不新增 Cargo 依赖。
- 不在本计划中锁定尚未验证的第三方库版本或平台 API 行为。
- 不把 Mermaid 图当作运行时契约；实现前仍需用代码和官方文档验证。

## 约束

- 以 `Cargo.toml`、`src/main.rs` 和现有设计文档为仓库事实；实现状态保持“尚未实现”的标注。
- 文档面向中文读者，所有结构图和流程图使用 Mermaid。
- 必须保留用户现有设计意图，同时补充 P0/P1/P2 优先级、验收和失败路径。

## 依赖关系

- 依赖已完成的上下文初始化扫描和当前设计文档。
- 不依赖生产代码变更、第三方服务或真实平台权限。

## 阶段

1. 盘点旧文档的产品目标、功能和技术选型。
2. 补齐功能规格、领域模型、模块边界、流程和非功能约束。
3. 用 Mermaid 绘制总览、架构、状态、时序和异常流程图。
4. 运行 Markdown/Mermaid 结构检查与 `ctx validate`，记录已知未知项。

## 退出标准

- 每个 P0 功能都有目标、入口、主流程、边界行为、错误反馈和验收标准。
- 存在功能模块总览图、软件架构图，以及截图、贴图、标注、OCR、热键、启动和导出流程图。
- 文档明确设计假设与当前实现状态的区别，未虚构依赖和平台能力。
- `context_bootstrap.py validate` 通过，工作区未提交、未推送。

## 检查点

- 重写前确认现有设计目标和当前实现状态没有混淆。
- 重写后检查 Mermaid 围栏、关键章节和 `ctx validate`。
- 用户审查前不提交、不推送。

## 计划级风险

- 设计细化可能超出当前极简代码基线；通过明确“目标设计，尚未实现”隔离风险。
- Mermaid 在不同渲染器中的兼容性存在差异；验证代码围栏、图类型和关键节点，具体渲染在文档平台上复核。

## 完成标准

- 设计文档具备可评审的功能契约、架构边界、关键流程和阶段拆分。
- 上下文校验通过，所有未知项和未实现项明确标注。
