# 计划 073：Overlay 选区物理像素读数

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/073_selection_metrics_readout.md`

## 目标

落实设计文档 6.1 的 Overlay 读数契约：在已有区域、全屏、虚拟桌面、窗口和编辑 Overlay 中，以原始截图物理像素显示当前有效选区的宽、高与全局左上坐标；普通拖选及四边/四角调整期间按现有节流刷新。读数只能绘制在已存在的 Overlay 帧中，Pinora 空闲继续只驻留系统 tray，任何辅助层都不得进入任务栏、Dock 或分页器。

## 非目标

- 不实现新窗口、浮动提示框、Toast、系统菜单、显示器枚举、跨显示器选区、截图后端、标注、导出、OCR、贴图或后台任务。
- 不改变资产格式、标注坐标、截图请求、`DisplayId` 语义、窗口策略或现有工具栏命中规则。

## 约束

- 尺寸和坐标必须从当前 `SelectionSession` 的缓冲选区经既有 `buf_rect_to_src` 映射得到，再叠加当前捕获会话的 `display_origin`；不可直接显示逻辑点或窗口坐标。
- 读数布局必须限制在当前 Overlay 图像 bounds 内，并与工具栏和选区边框保持可读距离；空间不足时应保持可见但不创建替代窗口。
- 绘制与脏区恢复必须覆盖旧读数区域，避免拖选、反向拖选、重选或取消后残留像素。
- 不增加窗口、事件循环、系统菜单、截图、worker 或可见性调用；继续受 `window_policy` 的隐藏创建和唯一展示入口守卫约束。

## 依赖关系

- 依赖 009 的 `SelectionSession` 与物理像素选区模型。
- 依赖既有 `buf_rect_to_src` 和捕获会话 `display_origin`，它们定义缓冲到源图及全局坐标的唯一映射。
- 依赖 061/066 的 tray-only GUI 会话和辅助窗口边界。
- 依赖 072 的现有 Overlay 拖动节流、热区调整和脏区呈现路径。

## 阶段

1. 建立纯读数模型与布局规则，覆盖原图尺寸、全局坐标、边界和工具栏避让。
2. 接入现有 Overlay 脏区绘制和拖动节流，确保普通拖选、键盘移动与热区调整都刷新读数。
3. 覆盖取消/重选残影、窗口策略守卫与全量离线质量门禁，并记录真实桌面风险。

## 检查点

1. 读数始终是物理源像素，且全局坐标包含负显示器 origin。
2. 所有读数与绘制都限定在既有 Overlay 的内存帧中；没有新增窗口或异步工作。
3. 拖选、反向拖选、八方向调整、重选和取消均不留下旧读数像素。

## 计划级风险

- 缓冲与源图映射混用可能造成 HiDPI 下尺寸/坐标误导；必须重用已有映射函数并用缩放、负 origin 回归锁定。
- 读数面板可能与工具栏或选区边框重叠，或未恢复旧脏区导致视觉残影；布局和损坏区域必须由纯函数与像素测试覆盖。
- 离线渲染无法证明 Windows、macOS、X11、KDE Wayland 的字体、缩放、任务栏/Dock/分页器隔离或连续拖动帧时间；不得将静态验证外推为原生桌面证据。

- 读数布局、映射、旧像素恢复和交互回归均有离线测试；未创建窗口、事件循环、系统菜单、截图或 worker。
