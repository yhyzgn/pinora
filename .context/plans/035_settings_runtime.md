# 计划 035：设置驱动运行时安全策略

- 状态：已完成
- 负责人：未分配
- 当前任务：`.context/tasks/035_settings_runtime.md`

## 目标

将 033 建立的版本化设置从“启动读取并打印状态”推进到实际运行时策略：贴图数量上限和新贴图默认不透明度在应用启动时生效，并通过纯逻辑测试锁定行为。

## 非目标

- 不实现设置窗口、热键录制、主题渲染、热更新或跨平台配置目录。
- 不把 `ThemeMode` 的持久化读取描述为 UI 主题已经生效。
- 不自动保存修复后的配置，不覆盖损坏源文件。

## 阶段

1. 让 `AppRuntime` 持有经过字段修复的设置，并将贴图上限映射到 core 状态。
2. 让桌面壳在创建新贴图时使用默认不透明度，并保留手动调整路径。
3. 完成入口加载、非敏感策略诊断、离线回归测试和质量门禁。

## 约束

- `AppRuntime` 持有已校验的 `AppSettings`，core 状态只接收合法的贴图上限。
- 桌面壳从 runtime 读取默认不透明度；用户运行时手动调整仍保持现有快捷键语义。
- 入口加载缺失/损坏配置时只使用内存默认，不产生写文件副作用。

## 依赖关系

- 依赖 033 的 `AppSettings`、`SettingsStore` 和缺失/无效状态语义。
- 依赖现有 `AppState.max_pins`、`PinWin.opacity` 和桌面壳生命周期。

## 检查点

- 启动加载结果映射为稳定 `AppSettings`，不把诊断字符串传入业务状态。
- `pin_limit` 限制 `CreatePin`/`CreatePinFromImage`；默认透明度仅影响新建贴图。
- 主题字段在日志中可见但不宣称已应用；设置加载失败不阻塞手动菜单能力。

## 计划级风险

- 当前 UI 没有设置页，用户只能通过文件格式或未来 API 修改设置；后续必须补 UI 与保存动作。
- 现有桌面壳仍是单体文件，新增字段只能保持最小接入，不能借机继续扩大重构范围。

## 完成标准

- 运行时和桌面壳使用设置策略，相关纯逻辑测试通过。
- 完整静态质量门禁、workspace 测试和 ctx 校验通过；文档明确主题未渲染及 UI 未交付。
