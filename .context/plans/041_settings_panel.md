# 计划 041：可操作设置面板

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/041_settings_panel.md`

## 目标

在既有版本化设置文件之上交付首个可操作的设置入口：用户可以查看并修改主题、历史条数、贴图上限和新贴图默认不透明度；修改经过领域校验后原子保存，保存失败不改变运行时生效值。

## 非目标

- 不实现跨平台原生设置控件、系统主题探测或完整无障碍读屏适配。
- 不改变设置文件格式、字段含义、热键协议、历史索引格式或公共命令字符串。
- 不在本任务接入历史浏览窗口、OCR 引擎配置和真实桌面 GUI 自动化。

## 约束

- 继续使用既有 `AppSettings` 校验和 `SettingsStore` 原子 codec；不得写半成品或覆盖损坏源文件。
- 草稿、磁盘值和 runtime 生效值分离；只有保存成功后才能应用策略。
- 面向人员的状态、日志和上下文记录不得包含路径、像素、OCR 全文或凭据。

## 依赖关系

- 依赖 033 的版本化设置存储和 035 的 runtime 设置接入。
- 复用 039 的 tombstone 文件清理事务，不新增删除路径。

## 检查点

- 设置文件写入失败时，runtime、历史索引和贴图默认值均保持保存前状态。
- 历史配额收紧时先保存 tombstone 索引，再执行受管文件清理；任一步失败都保留可重试状态。
- 设置窗口关闭、Esc 和再截图操作都释放窗口，不阻塞主事件循环。

## 计划级风险

- 自绘窗口未覆盖平台原生焦点、HiDPI、主题和无障碍语义；只能作为实验 UI 入口交付。
- `desktop_shell` 仍是大文件，新增窗口编排会增加拆分压力，后续需迁移到 UI Adapter。

## 阶段

1. 建立设置面板状态机、字段布局和命中测试。
2. 接入桌面 shell 独立窗口，支持键盘与鼠标编辑、保存、取消和错误回滚。
3. 将保存后的设置应用到运行时策略（贴图上限、默认不透明度、历史配额）。
4. 完成定向测试、全量质量门禁并更新事实与风险。

## 完成标准

- 控制窗口通过 `S` 或 `Ctrl+,` 打开设置面板。
- 主题、历史上限、贴图上限和默认不透明度均可查看、编辑、保存和取消。
- 保存失败时显示脱敏错误，运行时值和磁盘值都保持原值。
- `cargo test --workspace`、严格 Clippy、fmt、ctx validate 全部通过。
