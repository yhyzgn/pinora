# 计划 036：OCR 文字层拖选与复制

- 状态：已完成
- 负责人：未分配
- 当前任务：`.context/tasks/036_ocr_text_selection.md`

## 目标

将已有 OCR 词框从“只显示和全文复制”推进为可交互文字层：在贴图窗口内按拖拽矩形选中词，按 OCR 阅读顺序生成选中文本，并通过现有 `ExportJobService` 复制到系统剪贴板。

## 非目标

- 不更换 OCR 引擎、语言模型或模型分发策略。
- 不实现富文本编辑、词级置信度编辑、Overlay 内文字层或 OCR 结果持久化。
- 不把 fake OCR/剪贴板契约测试称为真实桌面复制验证。

## 约束

- core 只处理词框几何和文本顺序，不依赖窗口、剪贴板或平台 SDK。
- 贴图窗口使用 Ctrl+左键拖选，避免破坏现有普通左键拖动窗口行为。
- 文本复制必须走 `JobSupervisor`/`ExportJobService`，贴图关闭或资产代际变化时丢弃晚到结果。
- 日志不输出 OCR 全文。

## 阶段

1. 增加 `OcrTextSelection` 和按区域选词/生成文本 API。
2. 接入贴图窗口 Ctrl+拖拽、选中词框高亮和文本复制任务。
3. 覆盖空选区、跨行顺序、缩放坐标、关闭竞态和质量门禁。

## 依赖关系

- 依赖 023/024 的 `OcrJobService` 和 026/027 的受监督文本剪贴板任务。
- 依赖 035 的设置运行时接线，但不读取新增设置字段。

## 检查点

- 词框与选择矩形相交即可选中，结果按原 OCR 行/词顺序稳定输出。
- 贴图窗口关闭后选择复制任务被 owner 门禁拒绝；无词或空文本不提交任务。
- 缩放窗口的物理坐标正确映射回原图像素坐标。

## 计划级风险

- 不同 OCR 引擎对中文词切分不同；本任务只保证引擎返回词框的顺序和文本，不重写分词。
- Ctrl+拖拽是新增手势，Wayland 窗口管理器若不给焦点将保留现有键盘/托盘降级路径。

## 完成标准

- core 选择模型和 desktop shell 交互均有离线契约测试；真实桌面剪贴板仍单独记录验证状态。
