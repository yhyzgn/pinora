# 计划 089：托盘贴图列表与单贴图唤起

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/089_tray_pin_list.md`

## 目标

补齐设计文档定义的托盘“贴图列表”：托盘动态列出当前打开的贴图，用户选择任一条目时仅显示并聚焦该既有贴图窗口。列表在贴图创建、关闭及可见性变化后立即反映当前状态，并继续遵守 Pinora 的 tray-only 窗口隔离约束。

## 非目标

- 不新建贴图窗口、历史窗口、Overlay、线程、事件循环、截图路径、持久化字段或依赖。
- 不在托盘中显示截图内容、OCR 文本、文件路径、Pin 内部标题、领域 ID 或坐标。
- 不修改贴图的锁定、透明度、缩放、置顶、关闭、恢复或领域状态语义。
- 不将离线菜单测试或交叉编译表述为真实 Windows/macOS/X11/KDE Wayland 菜单、焦点或任务栏/Dock/分页器验证。

## 依赖关系

- 依赖 `tray-icon`/`muda` 已有的 `Submenu` 动态 append/remove API。
- 依赖 `desktop_shell` 作为贴图 `Window`、可见性和生命周期的唯一 owner。
- 依赖 `window_policy::show_auxiliary_window` 作为既有贴图恢复展示和任务栏/Dock/分页器隔离的唯一入口。

## 约束

- 动态菜单只在既有 GUI 事件循环线程中更新；更新失败不得改动 `pins`、领域状态或窗口可见性。
- 条目按 `PinId` 排序以保证重建稳定，但只能显示按顺序生成的通用名称和可见性；内部 ID 仅用于事件映射。
- 单贴图激活只能操作当前存在的 `PinWin`，并且展示必须唯一通过 `window_policy::show_auxiliary_window`。
- 关闭全部贴图时必须批量完成生命周期收敛后再刷新一次菜单，避免上限内重复重建造成无意义的 tray 开销。

## 阶段

1. 在 tray 适配器中定义不含敏感内容的贴图列表快照、动态子菜单和 `ActivatePin(PinId)` 动作，覆盖空列表、可见/隐藏列表和未知菜单 ID。
2. 在桌面壳将菜单动作映射回既有 `PinWin`，通过唯一窗口策略显示、聚焦并请求重绘；在所有贴图生命周期与可见性变化处同步列表。
3. 运行定向、workspace、跨 target、严格静态、差异和上下文门禁，并记录真实桌面验收缺口。

## 检查点

1. 动态子菜单仅展示稳定顺序的“贴图 1…N”和可见性状态；空列表显示禁用占位项，最多受既有 `max_pins` 约束。
2. 菜单项关联内部 `PinId`，但标签不泄露截图、OCR、路径、窗口 title、坐标或原始 ID。
3. 选择条目只对当前匹配的既有 `PinWin` 调用 `show_auxiliary_window`、`focus_window` 与 `request_redraw`；不存在的 PinId 安全忽略。
4. 创建、关闭、批量显示/隐藏、延时截图隐藏/恢复、编辑隐藏/恢复和编辑替换显示后列表状态一致；不增加展示入口。

## 计划级风险

- `tray-icon`/各系统 tray 后端的运行时子菜单刷新时机并不由离线测试证明；刷新失败不可破坏贴图状态，真实平台需单独验收。
- 显示并聚焦既有贴图仍依赖各窗口管理器实际执行任务栏/Dock/分页器隔离与焦点请求；沿用 `R-047` 的原生会话验证要求。

## 完成标准

- 托盘有随贴图生命周期更新的“贴图列表”子菜单，选择条目能显示并聚焦既有贴图。
- 标签不包含任何受保护的本地内容或内部标识；所有展示仍唯一经过 `window_policy`。
- 定向、workspace、跨 target、严格静态、差异和 `ctx validate` 通过；真实桌面行为明确登记为风险。

- tray 增加动态“贴图列表”子菜单。列表按 `PinId` 稳定排序，却只显示“贴图 N”及“可见/已隐藏”；空列表显示禁用占位项，菜单映射保留内部 `PinId` 而不显示它。
