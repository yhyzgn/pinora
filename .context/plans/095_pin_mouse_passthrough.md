# 计划 095：贴图鼠标穿透

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/095_pin_mouse_passthrough.md`

## 目标

为现有贴图提供临时鼠标穿透模式，让用户可将贴图作为只读参考层，同时通过既有 tray 贴图条目恢复该贴图的鼠标交互；不创建任何新窗口，也不将状态伪装为跨平台已验证能力。

## 非目标

- 不新增全局热键、平台特定 API、依赖、线程、设置 schema、持久化字段、点击穿透范围配置、透明窗口或动画。
- 不改变贴图图像、OCR、导出、锁定、透明度、置顶、PinId、历史、截图、owner/generation、tray-only 窗口策略或任务栏/Dock/分页器策略。
- 不承诺任一窗口管理器、合成器或桌面环境实际支持鼠标穿透；适配器返回失败时不得改变内存状态或报告成功。

## 依赖关系

- 依赖 `winit 0.30.13` 现有 `Window::set_cursor_hittest(bool)` 的成功/失败结果作为唯一状态提交门槛。
- 依赖 060 的贴图客户区菜单、066/061 的唯一 `window_policy` 展示入口，以及 089/090 的动态 tray 贴图列表与最近使用排序。
- 不向领域模型、设置、历史、关闭恢复快照或跨进程状态增加依赖；穿透状态随 `PinWin` 销毁而丢弃。

## 已验证前置事实

- 当前 `winit 0.30.13` 的 `Window::set_cursor_hittest(bool)` 在依赖源码中存在；Windows、macOS、Linux X11 与 Wayland 各有实现，移动/网页等不支持平台返回 `ExternalError::NotSupported`。
- 贴图已有客户区上下文菜单、动态 tray 贴图列表和单 `PinId` 激活入口；所有贴图窗口均由 `window_policy` 创建和展示。
- tray 条目当前仅暴露无内容的序号、可见性与进程内最近使用排序；可扩展状态标签而不泄露图像、路径、坐标或内部 ID。

## 约束

- 只有成功调用既有窗口的 `set_cursor_hittest(false)` 后，当前贴图才进入穿透状态；失败保留原交互状态并给出固定、脱敏的受限反馈。
- 启用后立即关闭当前客户区菜单、取消拖动/缩放/OCR 选择瞬态状态；贴图仍可见，窗口不再接收鼠标命中。
- tray 的同一贴图条目在穿透状态下表示“恢复交互”：先成功 `set_cursor_hittest(true)`，再显示、聚焦、重绘并更新无内容状态标签；失败保持穿透状态且不伪造恢复成功。
- 状态只存于当前 `PinWin` 生命周期，不进入领域模型、设置、历史、关闭恢复快照或跨进程恢复；关闭后自然丢弃。
- 所有交互仍在 GUI 线程发生；不新增窗口、展示入口、外部进程或敏感日志。

## 阶段

1. 在贴图运行时模型、客户区菜单和受控 tray 反馈中引入可恢复的临时穿透状态。
2. 在桌面壳中将菜单启用、平台调用、失败保留和 tray 激活恢复收敛为小型辅助函数。
3. 覆盖菜单可用性、状态标签脱敏、恢复选择、失败/陈旧动作和 tray-only 窗口策略回归。
4. 运行定向、workspace、跨 target、严格静态、差异和上下文门禁；将真实鼠标命中、焦点和窗口管理器差异记录为风险。

## 检查点

1. 未锁定或锁定贴图均可在客户区菜单请求鼠标穿透；成功后不存在可接收鼠标的客户区菜单或拖动状态。
2. tray 条目不泄露内容；穿透条目经同一 `PinId` 恢复路径成功后才回到可交互、可见且聚焦状态。
3. 平台调用失败、重复 tray 动作、未知 PinId 或关闭后的陈旧条目无 panic、无状态污染、无成功误报。
4. 没有新增建窗/展示路径，现有 `window_policy` 静态守卫与 workspace 回归保持通过。

## 计划级风险

- `set_cursor_hittest` 的目标平台实现不等同于具体合成器实际转发鼠标事件；Wayland/X11 输入区域、macOS 焦点与 Windows 窗口标志必须实机验证。
- 穿透后无法用鼠标直接操作贴图，因此 tray 恢复是唯一受支持的恢复路径；原生 tray 刷新和聚焦时序仍须验证。

## 完成标准

- 用户能在现有贴图菜单启用鼠标穿透，并可通过 tray 贴图条目恢复交互；平台失败不会造成不可恢复或伪成功状态。
- 状态不泄露内容、不持久化、不新建窗口，截图/OCR/导出/历史/贴图生命周期不受影响。
- 定向、workspace、跨 target、严格静态、差异和 `ctx validate` 通过；原生鼠标命中、tray、焦点、性能和窗口管理器行为如实保留为风险。

## 完成记录

- 已实现：`PinWin` 新增不持久化的 `PinMouseMode`。客户区 `PASS` 只有在 `set_cursor_hittest(false)` 成功后才进入穿透，并清理菜单、拖动、缩放、OCR 选择与双击瞬态状态；失败保留原状态及菜单。
- 已实现：动态 tray 列表仅以通用序号、可见性和穿透状态标记贴图。选择穿透条目时先恢复 `set_cursor_hittest(true)`，失败不显示、不聚焦、不重绘或推进最近使用；成功后复用既有展示、聚焦、重绘和最近使用路径。
- 已实现：tray 反馈增加固定、脱敏的贴图穿透启用、交互恢复和能力受限状态；受限状态只提供稳定 `CapabilityUnavailable`，不显示原始平台错误。
- 已验证：菜单、tray、反馈和状态提交定向测试通过；`cargo check --workspace`、`cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`PINORA_NO_SYSTEM_CLIPBOARD=1 cargo test --workspace`（app 280 通过、2 忽略；core 89 通过）、`cargo check --workspace --target x86_64-pc-windows-msvc`、`git diff --check` 与 `ctx validate` 通过。
- 未验证：真实 Windows/macOS/X11/KDE Wayland 鼠标输入区域、tray 动态刷新、焦点、性能、HiDPI 与任务栏/Dock/分页器行为；已登记为 `R-053`。
