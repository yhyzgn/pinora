# 计划 044：托盘菜单动作闭环

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/044_tray_actions.md`

## 目标

把托盘从“截图/退出”演示入口提升为可用的应用控制面板：设置、历史、显示全部、隐藏全部和关闭全部贴图均通过稳定动作进入桌面编排。

## 非目标

- 不在本任务引入新的托盘库、平台 SDK 或原生菜单主题。
- 不实现贴图列表子菜单、诊断导出、全屏截图新工作流或系统权限探针。
- 不将 Linux GTK/StatusNotifier 成功外推为 Windows/macOS 真实托盘验收。

## 依赖关系

- 依赖 041 设置窗口、042/043 历史窗口和既有贴图生命周期。
- 复用 `tray-icon` 的平台适配与已有 `AppTray::poll` 非阻塞事件模型。

## 约束

- `tray` 模块只定义菜单和动作映射，不直接持有 runtime、窗口或任务服务。
- 关闭贴图必须沿用既有 owner 取消和 runtime 状态同步路径。
- 不新增 warning suppression，不把无托盘环境当作失败启动。

## 检查点

- 菜单动作只发送意图，窗口/运行时状态由 `desktop_shell` 主线程修改。
- 关闭全部逐个复用 `close_pin`，确保 OCR/导出任务 owner 一并取消。
- 托盘创建失败时手动热键和控制窗仍可用。

## 计划级风险

- 不同平台托盘事件循环和菜单呈现未建立真实桌面证据；保持能力日志和降级入口。
- 隐藏贴图不应影响 runtime 状态，显示全部必须恢复可见窗口句柄。

## 阶段

1. 扩展托盘菜单项和动作 ID 映射。
2. 接入桌面 shell 设置、历史和贴图批量动作。
3. 完成静态门禁、离线测试和上下文更新。

- workspace 质量门禁、ctx validate 通过，真实平台托盘 GUI 缺口明确记录。
