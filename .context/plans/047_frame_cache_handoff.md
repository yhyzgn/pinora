# 计划 047：帧缓存零复制交接与暂停正确性

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/047_frame_cache_handoff.md`

## 目标

消除热键命中预截帧后对全屏 RGBA、原图 XRGB 和暗化 XRGB 的整帧克隆；将最新帧以一次性所有权移交给 Overlay，并阻止暂停后完成的后台截屏重新写入缓存，降低高分辨率下 Overlay 首帧延迟与陈旧/自截画面风险。

## 非目标

- 不把实验截图后端或后台预截机制描述为跨平台正式截图方案。
- 不改变 `CaptureProvider`、公开 IPC、设置、历史文件或贴图领域状态。
- 不实施跨显示器联合 Overlay、窗口截图、延迟截图或平台权限流程。

## 依赖关系

- 依赖既有 `CaptureProvider`、空闲预截循环与 Overlay 的 `PreparedPreview` 所有权边界。
- 复用 031 的 Overlay 像素缓冲契约；Overlay 持有独立、可变的绘制缓冲。

## 约束

- 缓存命中只能移交已验证的完整帧；不得将半成品或 Overlay 自身截图交给下一会话。
- 暂停期间已在执行的捕获可以自然结束，但不得发布到 `latest`。
- Overlay 仍保留自己的可变绘制帧缓冲；不得为避免复制而共享可变 UI 像素状态。
- 所有时间与性能说明必须来自代码路径和可重复测试，真实桌面端到端时延仍单独记录。

## 检查点

- 缓存命中在暂停前移交帧所有权，暂停只清理尚留在缓存槽位中的帧。
- `pause` 和 `resume` 只在状态转换时推进代际，重复恢复不能使正在进行的预截结果失效。
- 抓取结束时再比对暂停状态和代际，不匹配即丢弃，不触碰 `latest`。

## 计划级风险

- 一次性移交会使缓存槽位暂时为空；Overlay 关闭后恢复既有预截循环，未就绪时保留 cold capture 路径。
- 单元测试只能证明所有权与并发状态语义，不能测量 KDE、Wayland 或不同显示器的真实端到端时延。

## 阶段

1. 将 `FrameCache` 的读取 API 改为从 `latest` 移走帧，而不是克隆整帧数据。
2. 在后台捕获完成后再次检查暂停状态，丢弃暂停期间完成的帧。
3. 用确定性单元测试锁定移交与暂停后丢弃语义，并运行 workspace 门禁。

## 完成标准

- `take_if_fresh`/回退读取不会克隆已缓存的全屏像素缓冲。
- `pause` 生效后后台捕获的结果不会污染 `latest`。
- 新增回归测试和既有严格质量门禁通过；真实桌面时延未被虚构为已验证。

## 完成记录
