# 计划 096：历史保留天数

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/096_history_retention_days.md`

## 目标

把设计规格中“数量、最大磁盘占用和保留天数”的历史生命周期策略补齐为可配置、可迁移、可恢复的保留天数约束。过期记录必须先成为持久化 tombstone，再只清理 Pinora 受管目录内由索引管理的 PNG。

## 非目标

- 不在本任务新增最大磁盘占用设置、修改现有容量上限，或改变历史条目、PNG 索引、导出格式、内容哈希、OCR、预览、再次贴图和再次编辑行为。
- 不接管用户手动选择的外部导出路径，不扫描或删除未被历史索引直接引用的文件。
- 不新增窗口、事件循环、线程、外部进程、网络、权限或平台专有 API。
- 不将离线时钟、文件系统测试、target 编译或单元测试描述为真实桌面窗口、tray、文件系统中断恢复或跨平台行为验收。

## 依赖关系

- 依赖 `AppSettings`/`SettingsStore` 当前 v6 的固定长度 codec、设置面板共享布局和既有原子保存回读。
- 依赖 `HistoryIndex` 的数量/容量 tombstone、`HistoryStore` 原子索引写入、`history_export` 受管 PNG 白名单清理，以及桌面壳已有的启动/设置保存/导出完成生命周期。
- 不改变历史索引 schema、受监督导出 worker、窗口策略或 tray-only 展示边界。

## 已验证前置事实

- 设计文档 4.9 明确要求历史支持数量、最大磁盘占用和保留天数；当前设置只有 `history_limit`，运行时历史容量为 `u64::MAX`。
- 历史条目的 `created_at_ms` 来自 KDE/xcap 捕获的 Unix epoch 毫秒；历史索引已有原子保存、tombstone 和受管 PNG 白名单清理。
- 设置 codec 当前为 v6、27 字节，能读取 v1-v6；后续字段可通过 v7 追加而不重写旧格式。

## 约束

- 设置 schema 升级到 v7，在 v6 尾部追加小端 `u16` 的 `history_retention_days`；v1-v6 迁移均采用默认 30 天。
- 有效值严格限制为 `1..=3650` 天；无效 v7 数值只修复该字段，下次保存才原子写回当前格式。
- 历史领域只接收由应用层计算的截止 Unix 毫秒，不依赖设置或系统时钟；恰好在截止时刻的条目保留，早于截止时刻的活动条目才过期。
- 应用层读取 Unix 时间失败、保留天数到毫秒计算溢出时跳过本次时间淘汰，不把未知时间解释为过期。
- 启动、设置保存成功和受管 PNG 新增后都协调现有数量/容量配额、保留期和旧 tombstone；任何新 tombstone 必须先保存索引，保存失败时恢复内存索引。
- 清理继续复用既有白名单和活动同名保护，只删除受管目录直属、被 tombstone 索引引用的 PNG；删除或最终索引压缩失败时保留可重试 tombstone。

## 阶段

1. 将保留天数加入纯设置模型、修复记录和 v7 codec，并为 v1-v6 迁移及损坏 v7 字段建立回归。
2. 向 `HistoryIndex` 增加纯的截止时间淘汰操作，复用 tombstone 状态并锁定时间边界、非活动条目和排序不变量。
3. 在历史导出模块收敛“配额 + 保留期 + tombstone 清理”协调事务，并在启动、设置保存和新导出后接入。
4. 扩展设置面板、刷新历史窗口模型，运行完整门禁并记录真实系统时钟/文件系统恢复的残余风险。

## 检查点

1. v1-v6 读取不丢失已有字段，均以 30 天迁移；v7 保存与读取完全保留保留天数，非法值仅修复该字段。
2. 只有 `created_at_ms < cutoff_ms` 的活动条目成为 tombstone；同一时刻和未来时间戳不被误删，数量/容量淘汰语义不变。
3. 索引持久化失败不会留下仅内存中的过期状态；文件删除失败或最终压缩保存失败会保留持久 tombstone 以便下次重试。
4. 外部文件、嵌套路径、活动同名文件和不受索引管理的文件均不会被自动清理。

## 计划级风险

- 用户修改系统时钟会改变按期淘汰时机；当前策略在无法读取系统时间时保守跳过，但不提供跨设备可信时间源。
- 真实断电、网络文件系统、Windows/macOS 文件覆盖语义和高频历史窗口刷新尚无原生桌面验收，离线原子写与 tombstone 测试不能替代。

## 完成标准

- 用户可以在设置中编辑 1 至 3650 天的历史保留期；设置跨重启保存，v1-v6 设置安全迁移。
- 启动、成功保存设置和新的受管 PNG 历史记录都会按数量/容量/保留期协调并安全清理过期受管文件。
- 任何时间、索引或文件操作失败不伪造成功、不误删外部文件，并保留可恢复 tombstone。
- 定向、workspace、Windows target、严格静态、差异与 `ctx validate` 通过；真实平台时钟、文件系统中断恢复和桌面行为如实保留为风险。
