# 计划 080：桌面导出文件名分配

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/080_export_name_allocator.md`

## 目标

为既有桌面壳的异步 PNG 导出分配可读、稳定且普通冲突可递增的文件名，替代直接暴露内部 `ImageId` 的命名。分配器必须是可注入时间与文件存在性检查的纯逻辑；所有实际文件写入仍由既有 `ExportJobService` 和原子 PNG 路径执行。

## 非目标

- 不新增 JPEG/WebP、用户自定义模板、目录选择、覆盖开关、打开文件位置、文件浏览窗口或外部进程。
- 不改变 `ExportJobInput`、原子写入语义、历史索引格式、受管目录白名单、任务 owner/generation、系统剪贴板、公共命令或持久化设置形状。
- 不把单实例下的普通冲突规避表述为跨进程/恶意并发的无覆盖保证。

## 依赖关系

- 依赖 026/027 的受监督导出、028 的原子 PNG 写入、037 的历史记录接入和 078 的导出结果反馈。
- 复用 `AppRuntime::export_dir`、`ExportJobService` 与 `history_candidate_for_export`；仅在提交 `SavePng` 前替换文件名来源。

## 约束

- 名称只由 UTC 时间、进程内序号和固定 ASCII 组成，例如 `Pinora_20260802_143500.png`；不得包含截图内容、OCR、显示器名称、窗口标题、用户路径、内部 ID 或原始错误。
- 在同一秒或已存在同名时依次尝试 `_001` 至有限上限；无可用名称时受控失败，不能覆盖候选文件。
- 不在主事件循环进行图像编码或文件写入；路径检查为有限元数据操作，实际写入仍在既有 worker。
- 不新增窗口、事件循环、worker、网络、系统通知或真实共享基础设施访问；tray-only 和唯一辅助窗口展示入口不变。

## 阶段

1. 建立纯导出文件名格式与分配模型，覆盖 UTC 日历、同秒递增、磁盘冲突、上限和脱敏测试。
2. 在 `DesktopApp` 持有分配器，将 Overlay、贴图编辑、贴图自动保存和贴图菜单保存统一改用它。
3. 保持现有 `ExportJobService`、历史候选和 tray 反馈结果分支不变，运行定向与 workspace 门禁。

## 检查点

1. 用户导出的 PNG 使用可读 UTC 时间名，普通同秒/现存冲突不会覆盖既有候选。
2. 分配失败不会启动导出 worker、不会改变历史索引，也不会将失败表述为已保存。
3. 没有新窗口或异步模型；源码窗口策略守卫和全量离线测试保持通过。

## 计划级风险

- 单实例只能降低而不能消除候选检查与其他本地进程写入之间的竞态；本任务不将名称递增表述为跨进程无覆盖承诺。
- UTC 名称便于排序但不等于本地时区显示；自定义命名模板和覆盖策略须由后续设置任务单独覆盖。
