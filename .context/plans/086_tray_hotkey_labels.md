# 计划 086：tray 热键标签同步

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/086_tray_hotkey_labels.md`

## 目标

让 tray 的“截图”和“全屏截图”菜单标签始终反映已成功保存的区域/全屏主热键，避免 084 的可配置主键与固定 `F2/F3` 文案造成误导。

## 非目标

- 不增加或修改热键注册器、录制支持范围、设置 schema、IPC、备用键、Portal、平台权限或后台键盘监听。
- 不重建 tray、不创建窗口、事件循环、线程、进程、网络连接或新的依赖。
- 不将菜单标签与 OS 注册成功混为一谈；真实注册状态仍以能力摘要和诊断面板为准。

## 依赖关系

- 依赖 084 的受限 `HotkeyBinding`、`GlobalHotkeyHub` 预注册/回滚和原子设置保存顺序。
- 依赖现有 `AppTray` 菜单项可原地更新文本，以及 DesktopApp 的设置成功分支。

## 约束

- 初始 tray 标签从当前已校验设置产生；格式只消费受限 `HotkeyBinding::Display`，不得读取自由输入或后端 notes。
- 新标签仅在热键重绑和设置文件写入都成功后更新；注册失败、保存失败或回滚失败都保留旧标签。
- 标签更新不能改变任何 `TrayAction`、菜单 ID、实际热键映射或 tray-only 窗口隔离。

## 阶段

1. 将 tray 中两个主截图菜单项保留为可更新句柄，并从受限绑定生成初始标签。
2. 在设置成功提交时原地同步标签；失败和不可用后端保持现有标签与受控能力反馈。
3. 覆盖标签格式、初始参数、成功接线与失败不触发更新的纯逻辑边界，运行 workspace 门禁。

## 检查点

1. 默认设置仍显示 F2/F3；合法自定义组合显示对应组合，不泄漏换行、路径或原始错误。
2. 保存成功后 tray 的两项文本同步为同一份 `draft`；任何保存/重绑失败均不调用标签更新。
3. 菜单动作、备用键、IPC、诊断实际注册状态和辅助窗口策略保持不变。

## 计划级风险

- 通过离线格式和编译只能证明调用顺序，不能观察原生 tray 后端是否即时刷新文本；真实 Linux/Windows/macOS 菜单探针仍需要单独执行。
- 系统可能接受设置落盘但不支持全局注册；标签只表示持久化配置，不得当作能力状态或注册成功承诺。

## 完成标准

- 初始和成功保存后的 tray 菜单均从已校验绑定生成标签。
- 保存失败或重绑失败不改 UI 标签与已工作绑定；不创建任何辅助窗口或后台资源。
- 定向、workspace、跨 target、严格静态、差异和 ctx 验证通过；真实原生 tray 刷新保留为未覆盖风险。
