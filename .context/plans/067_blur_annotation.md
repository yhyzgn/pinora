# 计划 067：区域模糊标注

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/067_blur_annotation.md`

## 目标

补齐设计文档 4.4 的 P0 模糊工具：用户可在现有 tray 监督的 Overlay 中拖拽区域，以提交时冻结的半径对原始截图局部做确定性模糊；草稿预览、撤销重做、导出和贴图使用一致像素结果。实现必须线性遍历选区与有限采样边框，避免平方级模糊在连续拖拽时造成明显卡顿，不新增窗口、事件循环、截图或后台任务。

## 非目标

- 不实现高斯核、强度滑块、局部对象编辑、模糊笔刷、全图滤镜、持久化默认半径、GPU 后端或跨区域合并优化。
- 不重做渲染缓存、截图、贴图、OCR、导出、tray 或 `window_policy`。

## 约束

- 模糊工具仅影响有效矩形选区；半径由提交时线宽派生并受上限约束，后续线宽变化不改写旧对象。
- 使用原始不可变截图作为采样源，与既有马赛克一致；按文档顺序烧录时不修改源图，也不创建额外资产或 worker。
- 算法必须使用水平、垂直两次滑动盒模糊；临时内存仅覆盖选区宽度和有限纵向采样边框，不能为每个像素重复扫描二维核。
- 工具入口只扩展既有 Overlay 工具栏与 `B` 键；不推进窗口或 tray 状态，生产窗口仍只经 `window_policy`。

## 依赖关系

- 依赖 030 的标注 revision、预览和资产 generation 契约。
- 依赖 061/066 的 tray-only GUI 会话、隐藏创建和唯一辅助窗口展示入口。
- 依赖既有马赛克的原始源像素读路径与 `AnnotateSession` 草稿事务。

## 阶段

1. 扩展标注模型、草稿与提交半径冻结语义。
2. 实现分离滑动盒模糊并接入预览和最终烧录。
3. 增加工具栏、快捷键、核心像素和窗口策略回归，执行全量门禁。

## 检查点

1. 有效拖拽才创建 Blur 事务，半径冻结，撤销/重做与原有工具一致。
2. 渐变样例显示区域内变化、外部不变；预览与提交后输出逐字节相同。
3. 模糊入口不创建窗口、任务或截图，递归 `window_policy` 守卫保持通过。

## 计划级风险

- 大范围模糊仍在 Overlay 自绘线程执行；离线复杂度测试不能证明 4K/HiDPI 连续拖拽帧时间。
- 盒模糊是稳定、低成本的基础效果，不等同于高斯视觉；更高质量核须经独立性能任务评估。
- 真实任务栏/Dock、tray、焦点与合成器行为仍由 066 的原生桌面风险约束，不能因本任务关闭。
