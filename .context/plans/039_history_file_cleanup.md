# 计划 039：受管历史文件清理事务

- 状态：已完成
- 负责人：未分配
- 当前任务：`.context/tasks/039_history_file_cleanup.md`

## 目标

闭合历史索引配额淘汰后的本地文件生命周期：仅删除 `runtime.export_dir()` 直属、已 tombstone 且没有活动条目引用的受管 PNG；删除成功或确认文件已不存在后，才压缩并原子保存索引。

## 非目标

- 不提供历史窗口、预览、再次贴图/编辑、用户手动删除或清空全部。
- 不接管用户选择的外部导出目录，不扫描任意目录或删除不在索引中的文件。
- 不新增保留天数、最大字节数设置字段、后台清理线程或真实桌面探针。

## 约束

- tombstone 是持久删除意图：删除失败、目录类型冲突或仍被活动条目引用时不得 compact，保留记录供后续安全重试。
- 若进程在文件删除后、索引压缩前中断，启动后可再次看到 tombstone 并确认文件不存在后完成压缩。
- 索引压缩后的保存失败必须恢复本次内存索引；诊断只输出计数和稳定摘要，禁止输出绝对路径、像素或 OCR 全文。

## 阶段

1. 为 `HistoryIndex` 增加只压缩已确认 tombstone 的受限操作，并锁定其离线不变量。
2. 实现受管目录文件清理器，处理文件、符号链接、缺失文件、同名活动引用和删除失败。
3. 在受监督 `SavePng` 历史记录成功后执行清理并记录脱敏结果；保存失败时保留 tombstone。

## 依赖关系

- 依赖 034 的 `HistoryIndex` tombstone/原子 `HistoryStore`。
- 依赖 037 的受监督 PNG 历史候选、相对文件名及完成门禁。

## 检查点

- 绝不对 tombstone 外的文件执行删除；活动条目同名时绝不删除或 compact。
- 文件不存在视为已完成删除，可安全 compact；目录、权限或 I/O 失败保留 tombstone。
- 文件删除后 `HistoryStore::save` 失败时内存仍保留 tombstone，后续可恢复提交。

## 计划级风险

- 现有 `runtime.export_dir()` 是当前应用指定的受管导出根，尚未实现跨平台用户目录策略或历史 UI；清理不应外推为用户选择目录的通用删除能力。
- 该顺序不能抵抗底层文件系统、断电或跨设备 rename 的所有故障语义；真实平台恢复探针留待后续任务。

## 完成标准

- 清理器有删除、缺失、同名活动保护、删除失败和索引保存失败回滚的离线契约测试；workspace 质量门禁通过，真实桌面缺口明确记录。
