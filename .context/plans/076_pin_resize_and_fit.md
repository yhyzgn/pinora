# 计划 076：贴图边缘缩放与适应原图

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/076_pin_resize_and_fit.md`

## 目标

完成设计文档 4.3 中贴图窗口尚缺的高频尺寸操作：用户可拖动当前贴图四边或四角等比缩放，双击贴图或右键菜单可恢复 100% 原图尺寸。所有交互必须发生在既有贴图窗口内；Pinora 空闲时仍只在系统 tray 驻留，Overlay、贴图、历史、设置和任何辅助层均不得进入任务栏、Dock 或分页器。

## 非目标

- 不实现点击穿透、旋转、自由纵横比、窗口系统边框缩放、窗口标题/来源可访问性文本、贴图分组、标签、跨进程恢复或新的窗口类型。
- 不改变截图、标注、OCR、导出、历史、设置、tray 菜单、窗口创建策略、数据持久化形状或公共命令接口。

## 约束

- 尺寸与缩放计算必须提取为无窗口、无事件循环的纯逻辑；保持图像纵横比、最小尺寸、最大缩放和反向拖动的确定性规则。
- 四个角与四条边都按同一比例调整；拖动固定对边或对角锚点，不得在移动过程中创建窗口或重新截图。
- 使用 `request_inner_size` 和现有 `PinTransform.scale`，仅在实际尺寸变化时失效贴图渲染缓存与同步领域状态。
- “适应原图”只能复用当前 Pin 窗口，缩放恢复为 `1.0`；锁定贴图拒绝尺寸变换但仍允许关闭、复制、OCR 和菜单。
- 所有窗口继续只能经 `window_policy::create_auxiliary_window` 隐藏创建，并只由 `show_auxiliary_window` 显示；禁止策略模块外建窗、事件循环和显式显示调用。

## 依赖关系

- 依赖 053 的贴图基础帧缓存、060 的客户区右键菜单与 066 的窗口可见性策略。
- 依赖 `PinTransform` 的既有缩放范围和 `scaled_window_size` 的尺寸映射。

## 阶段

1. 为按边/角拖动的几何和 100% 恢复建立纯尺寸、比例与锚点模型及回归测试。
2. 接入当前贴图事件、客户区命中与 resize 指针提示，应用尺寸/位置变换并精确失效缓存。
3. 从当前贴图客户区菜单提供“适应原图”入口，覆盖锁定、边界、缩放同步和 tray-only 源码守卫。
4. 执行定向与全量离线门禁，更新上下文和风险登记。

## 检查点

1. 用户从任意边或角拖动都保持原始宽高比，越界/极小/反向拖动不产生零尺寸、跳变或超过既有缩放限制。
2. 热区与预览只在现有 Pin 窗口的自绘帧内；窗口数量、事件循环、展示入口和任务栏/Dock/分页器策略均不增加。
3. 滚轮缩放、右键菜单、锁定、OCR 拖选、关闭撤销和历史重新贴图保持既有行为。

## 计划级风险

- 边缘拖动与贴图拖动/OCR 文字选择可能竞争同一指针事件；必须有明确优先级与纯命中测试。
- 连续尺寸变更会触发缩放和缓存重建；只能在尺寸实际变化时申请重绘，真实 4K/HiDPI 帧时间不能由离线测试替代。
- Windows/macOS/X11/KDE Wayland 的无边框尺寸请求、焦点、任务栏/Dock/分页器和合成器映射不受单元测试保证，必须保留原生验收缺口。

## 完成标准
