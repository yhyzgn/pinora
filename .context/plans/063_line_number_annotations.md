# 计划 063：直线与序号基础标注

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/063_line_number_annotations.md`

## 目标

补齐设计文档 4.4 所列的两项高频基础标注：可按一次拖拽提交的直线，以及按一次点击提交、连续自动编号的序号标记。两个工具必须使用现有 Overlay、标注文档与渲染缓存，不创建新窗口、不重新截图，也不能改变 Pinora 仅由 tray 常驻的窗口边界。

## 非目标

- 不实现选择/编辑已有标注、圆角矩形、填充、模糊、文本框尺寸调整、序号样式面板、持久化默认值或屏幕全局取色。
- 不重写标注渲染架构、截图后端、OCR、导出、托盘、贴图或 `window_policy` 平台实现。

## 约束

- 直线、草稿预览和最终合成必须共享同一确定性栅格化路径，使用图像物理像素坐标；退化短线不得生成空事务。
- 序号点击必须立即形成一个标注事务，使用当前颜色和线宽派生的稳定视觉尺寸；每次成功提交才递增，撤销、重做或删除已提交项不重排已有编号；达到受限上限后停止提交，直到重新设置起始值。
- `AnnotateSession` 提供受边界约束的起始编号配置；编号计数不属于持久化格式，重选或关闭 Overlay 后按新的会话初始化。
- 工具栏和快捷键仅在现有 Overlay 客户区中切换工具；不得引入系统菜单、控制窗口、独立事件循环或直接窗口构造。
- 所有可见辅助窗口仍只能通过 `window_policy` 创建并应用既有任务栏/Dock 隔离策略；空闲进程继续只保留 tray、热键、IPC 与帧缓存。

## 依赖关系

- 依赖 030 的标注 revision、草稿和资产 generation 契约。
- 依赖 061 的单一受 tray 监督 GUI 入口与窗口创建源码门禁。
- 依赖 062 的自适应工具栏与取色后的当前颜色状态。

## 阶段

1. 扩展核心标注模型、会话手势和确定性栅格渲染，覆盖直线与序号的提交、预览、撤销/重做与编号边界。
2. 在 Overlay 工具栏和键盘输入中接入两个工具，确保一次点击序号不会进入拖拽或重选路径。
3. 增加定向回归测试，执行 workspace 严格门禁与上下文校验；记录真实桌面验证缺口。

## 检查点

1. 直线和序号均推进 revision 恰好一次；无效直线不推进 revision，序号操作不创建后台任务或资产 generation。
2. 序号值在起始值、连续点击、撤销/重做以及重新配置起始值的场景中可预测，不会重写已提交标注。
3. 生产源码仍仅由 `window_policy` 构造事件循环和窗口，新增入口只修改现有 Overlay 状态。

## 计划级风险

- 自绘文字的字形宽度、圆形抗锯齿、HiDPI 和读屏能力仍需真实 GUI 会话确认；离线像素测试仅证明确定性数据路径。
- 现有标注文档尚无持久化编解码器；新增枚举变体不能被误称为对外数据格式兼容承诺。
- 平台任务栏/Dock、KWin/Wayland 映射与输入延迟不能由 CI 或源代码门禁证明。

## 完成标准

- 工具栏和键盘均可选择直线与序号；直线拖拽和序号单击按各自单一事务提交，并即时显示确定性预览/合成结果。
- 序号从受约束起始值连续递增，撤销/重做或删除不修改已经提交的标记值；无效输入不污染文档。
- 未新增窗口、事件循环、平台菜单、截图或后台任务路径，`window_policy` 源码守卫持续通过。
- 定向测试、fmt、workspace check、严格 Clippy、全量离线测试、diff 检查和 `ctx validate` 通过；真实 GUI、HiDPI、任务栏/Dock 与性能缺口明确保留。
