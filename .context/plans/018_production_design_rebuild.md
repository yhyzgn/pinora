# 计划 018：生产级重构设计基线

- 状态：已完成
- 负责人：未分配
- 当前任务：`.context/tasks/018_production_design_rebuild.md`

## 目标

将 `docs/Pinora-开发设计文档.md` 从包含过期技术前提的产品愿景，修订为以接管审计为输入、能指导分阶段重构的生产级设计基线；明确功能契约、架构边界、平台能力和迁移规则，并用 Mermaid 图表达模块及关键流程。

## 非目标

- 不在本计划中重写运行时代码、引入 UI 框架或锁定第三方 SDK。
- 不把 Linux/KDE 实验实现、fake 截图或跳过的真实桌面测试描述为正式能力。
- 不删除旧模块；删除必须等替代路径具备等价契约测试后在后续任务执行。

## 约束

- 设计中的已验证现状、目标设计和待决策项必须分开标注。
- 所有功能均需描述入口、主行为、失败语义、状态归属和验收证据。
- 具体 UI 框架、平台 SDK、OCR 引擎、性能数值只列为待验证决策，不作为既定实现。
- Mermaid 图使用稳定的标准图类型；节点必须与正文模块名称一致。

## 依赖关系

- 依赖 `.context/tasks/016_takeover_audit.md` 的已验证接管结论。
- 依赖 `.context/tasks/017_rust_quality_baseline.md` 的静态质量门禁证据。
- 不依赖外部服务、真实桌面权限或未验证的第三方 SDK。

## 阶段

1. 根据 016 审计和 017 质量门禁修订文档元数据、事实边界和技术决策。
2. 明确目标模块、端口/适配器、应用状态机、任务监督和不可变图像资产生命周期。
3. 补充截图、贴图、标注、OCR、导出、平台降级、启动退出和迁移切换的流程/状态图。
4. 检查 Markdown/Mermaid 结构、上下文契约与工作区差异。

## 检查点

- 不保留将 GPUI/Liora、跨平台支持、fake 截图或 Linux/KDE 实验路径写成已交付能力的陈述。
- 每个 P0/P1 模块都包含入口、详细行为、失败语义、资产/权限边界和验收条件。
- 设计中的目标 crate 仅表达边界，不要求一次性拆分或新增依赖。

## 计划级风险

- 文档范围大，可能出现目标设计与现有代码重复或冲突；以第 0 节的三类信息边界和审计证据消除歧义。
- Mermaid 渲染器实现存在差异；本任务检查围栏、标准图类型和节点一致性，具体渲染以后续文档平台复核为准。
- 设计会暴露尚未选定的平台和 UI 技术；这些内容保留为待验证决策，不能作为实现完成的证据。

## 完成标准

- 文档包含功能模块总览、软件架构、能力探测、核心状态、任务生命周期、关键用户流程和迁移流程的 Mermaid 图。
