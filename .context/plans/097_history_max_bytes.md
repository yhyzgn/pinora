# 计划 097：历史最大磁盘占用

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/097_history_max_bytes.md`

## 目标

把设计规格 4.9 中“历史最大磁盘占用”从固定的 `u64::MAX` 收敛为可配置、可迁移、可恢复的字节配额，并复用现有历史 tombstone 事务，确保超额历史只在索引持久化后清理 Pinora 受管 PNG。

## 非目标

- 不修改历史索引 schema、PNG 编码、内容哈希、OCR、预览、再次贴图、再次编辑或删除语义。
- 不接管用户主动选择的外部导出路径，不扫描或删除未被历史索引直接引用的文件。
- 不新增窗口、线程、后台任务、外部进程、网络、权限或平台专有 API。
- 不把离线测试、target 编译或静态源码守卫描述为真实桌面、文件系统中断恢复或跨平台 GUI 验收。

## 依赖关系

- 依赖 096 的 v7 设置 codec、`history_retention_days` 和 `reconcile_history_policy`。
- 依赖 `HistoryIndex::set_limits` 已按活动条目字节总量从最旧到最新产生 tombstone。
- 依赖 `HistoryStore` 使用运行时配额加载索引并在原子保存后回读验证。
- 不改变设置窗口、tray-only 窗口策略和受监督导出 worker 的所有权边界。

## 约束

- 设置 schema 升级到 v8，在 v7 记录尾部追加小端 `u64` 的 `history_max_bytes`；v1-v7 读取均迁移到默认 1 GiB。
- 有效值严格限制为 16 MiB 至 64 GiB；非法 v8 值只修复该字段，下次保存才原子写回当前格式。
- 应用层将字节配额直接传给 `HistoryStore`/`HistoryIndex`；领域层不读取文件系统容量，也不把无法统计的文件解释为已清理。
- 启动、成功保存设置和受管 PNG 新增后继续统一协调数量、容量、保留期和 tombstone；新 tombstone 持久化失败时回滚内存索引。
- 面板以整数 MiB 展示，步长 64 MiB，超过 1 GiB 以 GiB 展示但底层始终保存精确字节值；边界点击和键盘步进不得溢出。

## 阶段

1. 在纯设置模型中定义默认值、范围和逐字段修复，并将固定长度 codec 升级到 v8，保留 v1-v7 读取。
2. 将容量行接入设置面板，验证键盘、鼠标、布局和单位显示。
3. 将保存后的容量传给 `HistoryStore`，复用既有 tombstone 协调器，并以容量下调场景锁定最旧优先清理。
4. 运行定向和 workspace 门禁，记录事实与残余原生桌面风险。

## 检查点

1. v8 设置精确保留容量；v1-v7 迁移默认 1 GiB，非法 v8 容量不影响其他字段。
2. 容量从 1 GiB 下调时，最旧活动条目先持久化为 tombstone；失败时索引内存完整回滚。
3. 仅在受管目录直属 PNG 上执行清理，缺失/删除失败/最终压缩失败保留可重试 tombstone。
4. 容量行、保存、取消、主题和其他设置字段的既有契约持续通过。

## 完成标准

1. v8 设置往 v7 末尾追加 8 字节；v1-v7 安全迁移到默认 1 GiB，非法 v8 容量只修复容量字段并保留其他字段。
2. 启动、设置保存和受管 PNG 新增使用用户容量配额；活动历史总字节超过配额时最旧条目成为 tombstone，数量与保留期语义不变。
3. tombstone 先原子保存，保存失败恢复内存索引；文件删除或最终压缩失败保留可重试 tombstone，不删除外部、嵌套或活动同名文件。
4. 设置面板支持容量边界、键盘/鼠标步进、取消和保存失败；布局无重叠，现有主题与其他字段不回归。
5. 定向测试、workspace 门禁、Windows target 检查、差异检查和 `ctx validate` 通过。

## 计划级风险

- 风险：旧版本无容量上限，迁移到默认 1 GiB 可能在首次启动时清理超额受管历史。缓解：默认值固定、日志只记录计数摘要，清理仍遵守 tombstone 白名单事务。
- 风险：文件大小与索引 `byte_len` 不一致时无法证明容量已释放。缓解：继续只依据索引元数据做 tombstone，清理失败保留 tombstone，完整性校验仍拒绝不匹配 PNG。
- 回滚：移除 v8 字段和面板行，恢复 `HISTORY_MAX_BYTES = u64::MAX`；历史索引格式与既有 tombstone 保持兼容。
