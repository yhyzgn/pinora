# 计划 075：贴图关闭撤销

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/075_restore_closed_pin.md`

## 目标

落实设计文档 4.3 的 P1 关闭撤销入口：用户关闭最近一个贴图后，可从 tray 触发一次恢复，恢复截图像素、位置、缩放、透明度、锁定与置顶状态。关闭结果必须使旧 owner 和窗口彻底失效；恢复创建新的 `PinId`、新的受 `window_policy` 隐藏创建的辅助窗口，不能伪造旧句柄或接收旧 OCR/导出结果。空闲 Pinora 仍只驻留系统 tray，任何辅助层均不得进入任务栏、Dock 或分页器。

## 非目标

- 不实现多级关闭历史、跨进程持久化、关闭动画、全局撤销栈、恢复 OCR 结果、恢复旧任务、点击穿透或窗口缩放改造。
- 不改截图、标注、导出、OCR、历史、设置、系统菜单以外的 tray 恢复项、窗口策略或后台执行模型。

## 约束

- 最近关闭快照仅保存在 `DesktopApp` 内存；只保存不可变图像和领域/呈现值，不保存 `Window`、`Surface`、`JobOwner`、OCR 或导出任务句柄。
- 关闭先取消旧 owner 任务并从 runtime 移除，再记录快照；恢复必须经 `Command::create_pin` 和 `spawn_pin` 创建新的领域/窗口身份。
- tray “撤销关闭贴图”在没有快照时禁用/忽略，恢复失败保留快照以便重试，不隐藏失败。
- 不新增窗口、事件循环、可见性调用、截图或 worker；恢复窗口继续只经 `window_policy` 隐藏创建和唯一展示入口。

## 依赖关系

- 依赖 `Pin`、`PinTransform`、`Command::create_pin/close_pin` 和 `JobSupervisor` owner 关闭语义。
- 依赖现有 `spawn_pin`、tray action 分发及 061/066 的 tray-only 窗口边界。

## 阶段

1. 建立不含平台句柄的最近关闭快照和纯恢复资格规则。
2. 在关闭/恢复路径接入 runtime、任务关闭、tray 动作和受策略保护的贴图创建。
3. 覆盖空快照、恢复成功/失败保留、变换保持、owner 失效和窗口策略门禁，更新上下文。

## 检查点

1. 关闭后的旧 `PinId`/owner 不能复活；恢复使用新 identity 与新窗口。
2. 最近快照只恢复一次，失败可重试，且恢复保留位置、缩放、透明度、锁定与置顶值。
3. 不产生任务栏/Dock/分页器窗口，空闲只由 tray 驻留。

## 计划级风险

- 混用旧/新 owner 会让迟到 OCR 或导出结果写入恢复贴图；必须在 close 时关闭 owner、恢复使用新 asset 和 pin identity。
- 窗口恢复失败可能丢失截图；必须在成功后才消费快照。
- 静态窗口策略和离线测试无法证明原生 tray、任务栏/Dock/分页器、焦点和恢复首帧；不外推为真实桌面证据。

## 完成标准

- 用户可从 tray 撤销最近一次贴图关闭，恢复当前图像与显示变换；旧任务不再影响恢复贴图。
- 恢复逻辑、tray 动作、失败保留和窗口策略有回归测试，且不创建未受策略保护的窗口。
- 定向测试、fmt、workspace check、严格 Clippy、全量离线测试、差异检查和 `ctx validate` 通过；真实桌面 tray、任务栏/Dock/分页器、焦点、首帧和性能明确保留。

## 完成记录

- 已完成：tray 增加初始禁用的“撤销关闭贴图”动作。最近关闭快照只保存图像、窗口位置、缩放、透明度、锁定和置顶，不保存窗口、surface、OCR、导出或 owner。
- 已完成：关闭先取消旧 owner 并从 runtime 移除，再启用撤销；恢复经新的 `Command::create_pin` 和既有 `spawn_pin` 生成新 `PinId`/asset/window，成功才消费快照。窗口创建失败会关闭刚创建的领域 Pin 并保留快照；“关闭全部贴图”清除单项撤销。
- 已验证：tray 定向、workspace check、严格 Clippy、全量离线测试、差异检查和 `ctx validate` 通过。全量离线结果为 app 183 通过、2 忽略，core 85 通过。
- 未验证：真实 Windows、macOS、X11、KDE Wayland 的 tray 菜单启用态、恢复首帧、任务栏/Dock/分页器隔离、焦点和大图恢复帧时间。
