# 计划 049：历史图像再次编辑

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/049_history_editing.md`

## 目标

将经过完整性校验的受管历史 PNG 重新放入 Overlay 标注工作流。用户可在历史窗口使用可见“编辑”按钮或 `E` 键打开原图，初始选区覆盖整个历史图像，并复用既有标注、撤销重做、OCR、复制、保存和贴图链路。

## 非目标

- 不修改历史索引、PNG 格式、tombstone 清理、搜索、删除或既有 Enter“贴图”行为。
- 不保存可编辑标注文档到历史索引，也不把旧 `ImageId`、旧 generation 或旧 OCR 结果复用到新会话。
- 不实现贴图窗口再次编辑、标签、异步缩略图、跨显示器坐标恢复或真实 GUI/HiDPI 验收。

## 依赖关系

- 依赖 042 的历史浏览、受管路径约束和 `load_history_image` 完整性校验。
- 依赖 031/032 的 Overlay 标注资产身份、revision 与撤销重做语义。
- 依赖 047 的帧缓存暂停代际，避免编辑窗口被后续预截帧捕获。
- 依赖 050 的仅托盘辅助窗口策略；历史编辑窗口不得新建任务栏入口。

## 约束

- 历史编辑必须先完成文件名、常规文件、长度、摘要、PNG RGBA8、尺寸和元数据校验；失败不得创建 Overlay 或 Pin。
- 捕获启动方式与 Overlay 初始选区必须分离。历史编辑是“完整图像初始选区”，不是一次新的全显示器捕获。
- 新会话仅消费 `load_history_image` 分配的新运行时 `ImageId`；`refresh_overlay_ready` 继续创建独立 annotation asset 和 revision。
- 编辑 Overlay 打开前暂停帧缓存；打开失败须立即恢复。完成、取消或再截继续走现有恢复路径。
- 历史图像使用独立常规编辑窗口，不假定历史来源显示器仍存在，也不伪造当前桌面的全屏映射。

## 检查点

- `E` 与可见编辑按钮只在选中条目时产生 `Edit` 动作；Enter 仍只产生 `Reopen`（贴图）。
- 成功编辑时历史窗口关闭，Overlay 进入 `Ready`，选区精确覆盖历史图像本地像素边界。
- 加载或窗口创建失败时历史窗口保留，显示既有失败状态，帧缓存不保持暂停。
- 历史编辑产物沿既有会话边界导出，不覆盖原受管 PNG 或历史条目的不可变身份。

## 计划级风险

- 历史图像首次读取和解码仍同步运行于桌面事件循环；大图或慢盘会造成短暂卡顿，未在本任务中引入后台缩略图。
- 普通编辑窗口的实际尺寸、焦点、缩放与任务栏隔离仍依赖真实桌面环境；离线测试不能代替 HiDPI、多显示器和窗口管理器验收。

## 阶段

1. 扩展历史面板动作、键盘和按钮布局，并锁定纯状态测试。
2. 将 Overlay 的捕获模式、初始选区和窗口呈现方式拆开，建立历史图像目标的纯逻辑契约。
3. 接入安全加载到编辑 Overlay 的 shell 编排，覆盖失败恢复并运行质量门禁。

## 完成标准

- 受管且校验通过的历史图像可进入独立编辑 Overlay，并以全图有效选区开始。
- 所有失败分支保持历史窗口可用，不创建 Pin，不残留暂停的帧缓存。
- 相关契约测试、workspace 严格门禁和 ctx validate 通过；真实桌面窗口、HiDPI 和多屏验证缺口明确保留。
