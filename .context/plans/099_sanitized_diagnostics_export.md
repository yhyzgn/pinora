# 计划 099：脱敏诊断包导出

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/099_sanitized_diagnostics_export.md`

## 目标

为诊断面板增加用户主动触发的本地脱敏诊断包导出，形成可复现、可审查、不可包含图像内容的故障反馈材料。

## 非目标

- 不导出截图、贴图像素、OCR 全文/词框、系统剪贴板内容或原始错误字符串。
- 不自动上传、联网提交、打开文件选择器或引入新的第三方依赖。
- 不改变现有诊断面板的能力判定、托盘驻留、窗口策略和业务状态。

## 约束

- 报告字段只能来自固定白名单；不得把任意 `String` 错误、路径或用户内容交给报告模型。
- 写入沿用现有本地导出目录，只在用户主动选择托盘动作后执行，不连接真实共享基础设施。

## 依赖关系

- 依赖现有 `DiagnosticsPanel`、`TrayFeedback`、`AppTray`、`AppRuntime` 和导出目录。
- 依赖 workspace 现有原子文件写入约定；不新增第三方依赖或持久化 schema。

## 范围

- 新增纯数据诊断报告模型和原子文件写入器。
- 托盘增加“导出诊断包”动作；成功后写入 Pinora 管理导出目录并显示固定脱敏反馈。
- 补充单元/契约测试、上下文事实和风险记录。

## 阶段

1. 定义固定字段报告模型和原子写入器。
2. 接入托盘动作与固定成功/失败反馈。
3. 运行定向测试和 workspace 门禁，更新上下文。

## 检查点

1. 报告字段白名单和敏感字段排除测试通过。
2. 托盘动作映射和失败反馈测试通过。
3. workspace check、Clippy、测试和 `ctx validate` 通过。

## 验收标准

1. 报告只包含固定版本、平台标签、能力布尔状态、稳定错误码、受限反馈枚举和非敏感设置摘要。
2. 报告内容不包含像素、OCR 文本、剪贴板、绝对路径、用户名、token 或任意原始后端错误。
3. 写入使用同目录临时文件、同步、原子替换和可读性校验；失败不发布成功反馈。
4. 托盘动作只在用户主动选择后执行，执行期间不创建额外窗口、不离开 tray-only 生命周期。
5. 定向测试、`cargo fmt --check`、workspace check、严格 Clippy、workspace 测试、`ctx validate` 和 `git diff --check` 通过。

## 完成标准

- 所有验收标准均有源码或命令证据，且上下文已区分已验证事实与开放原生探针风险。

## 风险与回滚

- 风险：诊断字段未来扩展时误把路径或原始错误带入报告；缓解：报告模型只接受已脱敏枚举/布尔值，禁止任意字符串字段。
- 风险：导出目录不可写或同名文件冲突；缓解：固定命名分配、原子临时文件和受控错误反馈。
- 回滚：删除导出动作与模块；不改动已有诊断面板和运行时能力状态。
