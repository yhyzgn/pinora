# 计划 069：标注整体清空事务

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/069_clear_annotation_transaction.md`

## 目标

落实设计文档 4.4“清空标注可整体撤销”的 P0 交互。当前 `AnnotationDoc` 只把单个新增对象放入 redo 栈，需升级为内部事务历史：清空当前全部标注作为一个可撤销/重做事务，并在既有 Overlay 工具栏提供入口。实现不能改变已有单条新增、撤销/重做顺序、revision 单调性、资产 generation、导出像素、tray-only 或任务栏/Dock 策略。

## 非目标

- 不实现对象选择、局部删除、批量选择、清空确认弹窗、跨会话历史、持久化事务或贴图内对象编辑。
- 不修改截图、贴图、OCR、导出、窗口工厂、平台策略或后台任务。

## 约束

- 事务历史必须在内存中保留足够的对象快照，使清空后一次 undo 恢复原有绘制顺序，一次 redo 再次整体清空。
- 无标注时清空不改变 revision、redo 分支或显示缓存；清空后新增对象必须清除 redo 分支。
- 工具栏入口只操作当前 Overlay 的 `AnnotationDoc`，不创建窗口、系统菜单、任务或截图。
- Pinora 空闲时只能由系统 tray 常驻；Overlay、贴图以及任何辅助层均不得产生任务栏、Dock 或分页器项。本任务仅复用既有 `window_policy` 路径，不得绕过它。

## 依赖关系

- 依赖 030 的 revision、redo 与 asset generation 契约。
- 依赖 015/062 的 Overlay 工具栏命中和窄画布布局。
- 依赖 061/066 的 tray-only GUI 会话和唯一辅助窗口映射入口。

## 阶段

1. 将内部 redo 状态升级为新增/整体清空事务，保留既有单条 API 兼容性。
2. 新增工具栏清空动作与 Overlay 状态机接入。
3. 覆盖清空、undo/redo 交错、redo 分支、revision/预览缓存和窗口策略回归，执行全量门禁。

## 检查点

1. 多条标注整体清空后，undo 恢复原顺序，redo 再次清空。
2. 清空前后导出/预览和 asset generation 遵从已存在 revision 契约；空文档清空无副作用。
3. 入口仅重绘现有 Overlay，不出现新任务栏/Dock、tray、窗口或任务路径。

## 计划级风险

- 历史事务快照会在清空时额外复制对象向量；仅在用户明确清空时产生，清空历史随新编辑清除，真实大文档内存仍待测。
- 工具栏增加一个控件可能影响窄画布换行；已有布局测试必须扩展，真实 HiDPI/无障碍仍未验证。
- 静态窗口策略守卫不能证明系统窗口管理器最终不会展示辅助窗口；真实 Windows、macOS、X11 和 KDE Wayland 的 tray、任务栏/Dock、分页器、焦点和首帧验证仍是交付前置条件。

## 完成标准

- 清空是一个有效事务：多对象一次清空、一次 undo 完整恢复、一次 redo 再次清空；空清空无副作用。
- 工具栏入口与既有缓存/revision 流程一致，不新增窗口或任务路径。
- 定向测试、fmt、workspace check、严格 Clippy、全量离线测试、差异检查和 `ctx validate` 通过；真实桌面交互、HiDPI、tray 和任务栏/Dock 验证缺口明确保留。
