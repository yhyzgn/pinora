# 计划 053：贴图渲染缓存与无关重绘隔离

- 状态：已完成
- 负责人：Codex
- 当前任务：`.context/tasks/053_pin_render_cache.md`

## 目标

为每个贴图窗口缓存与其当前窗口尺寸和不透明度匹配的基础 XRGB 帧。OCR 词框、文本拖选、锁定边框、焦点和其他仅叠加层的重绘必须复用该帧，不能再次对完整图像执行缩放或不透明度压暗。

## 非目标

- 不修改贴图领域状态、图像数据、OCR 内容、导出、历史、窗口策略或任务栏/Dock 行为。
- 不新增 GPU 渲染、真实透明合成、点击穿透、动画框架、后台渲染线程或依赖。
- 不将离线缓存测试说明为真实帧率、多显示器、HiDPI 或原生窗口性能验收。

## 依赖关系

- 依赖 047 的 XRGB 帧转换和 052 的历史贴图预处理输出。
- 依赖 036 的 OCR 词框和文本选择叠加；缓存只包含源图与不透明度，不包含会变动的 OCR 或锁定装饰。
- 依赖 050 的统一辅助窗口策略；本任务不创建新窗口且不能绕开 `window_policy`。

## 约束

- 缓存键至少包括来源图像像素、目标窗口物理尺寸和当前不透明度；任一项变化时才失效并重建。
- `paint_pin` 在缓存有效时只复制基础帧，再绘制 OCR、拖选和边框；不得再次调用整图 `scale_nearest` 或 `apply_opacity_darken`。
- 贴图 resize、缩放和不透明度变更仍在主线程保持原有交互与 `PinTransform` 同步；缓存错误不得创建额外窗口、阻塞退出或改变领域状态。
- 历史重新贴图的预处理 XRGB 必须继续直接进入贴图基础帧，不能回退到 RGBA 转换。

## 检查点

- 同一尺寸、不透明度下的 OCR/边框重绘不发生完整图像缩放或压暗。
- 尺寸或不透明度变化后仅重建一次匹配帧，结果像素与原有缩放/压暗顺序一致。
- 关闭、隐藏、锁定、OCR 选择和托盘的贴图操作语义保持不变。
- 纯缓存、pin 变换及既有 workspace 回归在严格门禁下通过。

## 计划级风险

- 每个可见贴图会额外保留一份当前显示尺寸的 XRGB 帧；按贴图上限约束且随窗口关闭释放，不扩大历史或导出数据。
- resize 期间仍需重建目标尺寸帧；本计划消除无关重绘重复计算，但不伪造连续 resize 的真实帧率保证。
- 缓存失效遗漏可能显示陈旧不透明度或尺寸；需要纯像素契约和事件路径回归覆盖。

## 阶段

1. 提取可测试的贴图基础帧生成与缓存身份，锁定缩放/不透明度像素语义。
2. 在贴图创建、resize、缩放和不透明度变化路径维护缓存，使 paint 只做复制与叠加。
3. 执行严格门禁与 CI，记录真实 GUI 性能缺口。

## 完成标准

- 有效贴图基础帧在无关重绘中不重新缩放或压暗完整图像。
- 尺寸、不透明度和来源像素变化都能正确使缓存失效，原有贴图交互不回退。
- 定向测试、workspace 严格门禁、ctx validate 和 GitHub CI 通过；真实窗口性能缺口如实记录。
