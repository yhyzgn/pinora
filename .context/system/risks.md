# 风险登记

## R-001：设计目标与实现状态混淆（中）

- 证据和影响范围：`docs/Pinora-开发设计文档.md` 描述完整桌面工具；代码已有运行时/fake 捕获/单实例，但仍无 GPUI、真截屏、OCR。
- 触发条件：把 GPUI/Liora、OCR、Wayland Portal 等选型文字当作已实现契约。
- 失败模式：引入错误版本或未授权的外部服务，导致构建、平台兼容或权限流程不可验证。
- 缓解措施和验证：每项生产变更先建立独立计划/任务，引用源码和命令证据；依赖引入后执行 `cargo metadata`、`cargo check` 和定向测试。
- 回滚或隔离：在任务边界内撤销新增依赖和模块；保留设计文档不变。
- 负责人和状态：未分配；开放。

## R-002：业务测试覆盖偏窄（中）

- 证据和影响范围：2026-08-01 的 `cargo test --workspace` 通过 122 个可执行单元测试（app 78、core 44），覆盖运行时、贴图、fake 捕获、OS 单实例、Overlay 标注 undo/redo 资产 revision 与任务服务契约，但不覆盖 GUI 与真实屏幕。
- 触发条件：开始实现 OCR 或真实平台捕获而不先锁定行为。
- 失败模式：编译通过但交互、状态转移或平台分支回归无法发现。
- 缓解措施和验证：每个功能任务先补充最小纯逻辑测试；平台集成使用隔离探针，不连接共享基础设施。
- 回滚或隔离：按任务回滚实现，保留新增回归测试以复现问题。
- 负责人和状态：未分配；开放。

## R-003：单实例仅为内存协议（中）— 已缓解（Unix）

- 证据和影响范围：主路径已用 `OsSingleInstance`（flock + Unix socket Activate）；`InMemorySingleInstance` 仅测试。
- 关闭/缓解证据：`os_instance` 测试与双进程探针确认二次启动转发 Activate（2026-07-30）。
- 残留风险：非 Unix 平台未实现；异常退出可能残留 sock（Drop/release 尽力清理）。
- 负责人和状态：未分配；Unix 已缓解，跨平台开放。

## R-004：真实捕获能力未验证（高）— fake 回退已移除

- 证据和影响范围：启动 `SelectedCaptureProvider::autodetect` 按 KDE → xcap 探测；两者均失败时进入 `Unavailable`，实际截图调用返回 `CapabilityUnavailable`，不再构造 fake 图像。
- 关闭/缓解证据：`capture_select::tests::no_real_backend_enters_unavailable_state_without_fake` 以及 workspace 质量门禁于 2026-08-01 通过。
- 残留风险：本轮未获授权运行真实桌面探针；无 pipewire/gbm、桌面权限或非 KDE 环境仍可能无法使用真实捕获，且受限 UI 恢复入口尚未完成。
- 负责人和状态：未分配；fake 回退已缓解，真实桌面验证和用户可见恢复路径开放。

## R-005：xcap 系统依赖与链接体积（低）

- 证据和影响范围：依赖 pipewire/gbm/wayland；`cargo` 依赖树显著增大。
- 触发条件：最小环境构建。
- 失败模式：缺 `.pc` 文件导致编译失败。
- 缓解措施：在 conventions 记录 dnf 安装命令；CI 安装对应 -devel。
- 负责人和状态：未分配；开放。

## R-006：桌面壳单体化导致架构不可控（高）

- 证据和影响范围：`crates/pinora-app/src/desktop_shell.rs` 共 2859 行，统一处理窗口事件、截图线程、Overlay 帧缓冲、标注、贴图、OCR、托盘和 IPC；最近多个提交集中修改该文件。
- 触发条件：继续向现有事件循环增加工具、平台分支或异步任务。
- 失败模式：输入状态互相污染、窗口关闭/重截竞态、性能修复反复回归，无法对单个能力做隔离测试。
- 缓解措施和必需验证：冻结现有 UI 行为作为回归场景；拆出应用状态机、窗口适配、Overlay 渲染、贴图控制器和异步任务边界；每层有 fake 契约测试和至少一条桌面探针。
- 回滚或隔离动作：按新 crate/模块边界分阶段迁移；旧壳保留到新主路径通过同等场景验证后再移除。
- 负责人和状态：未分配；开放。

## R-007：所谓跨平台能力实际绑定 Linux/KDE（高）

- 证据和影响范围：`src/main.rs` 和 `os_instance.rs` 直接使用 Unix socket；KDE 捕获依赖 `spectacle`、`kscreen-doctor`；剪贴板依赖 `wl-copy`/`xclip`/`xsel`；无 `cfg` 平台模块。
- 触发条件：在 Windows/macOS 或非 KDE Linux 上发布，或把 target 编译通过当作跨平台交付。
- 失败模式：无法构建、无法启动、捕获/热键/剪贴板不可用，且降级状态对用户不透明。
- 缓解措施和必需验证：建立 `PlatformServices` 能力接口和逐平台 adapter；先使 core 在所有 target 编译，再分别验证捕获、窗口、热键、剪贴板和单实例。
- 回滚或隔离动作：默认只声明已验证的平台；未验证平台隐藏为实验状态，不伪造支持。
- 负责人和状态：未分配；开放。

## R-008：发布质量门禁仍不完整（中）— 部分缓解

- 证据和影响范围：2026-08-01 已验证 `cargo fmt --check`、`cargo check --workspace` 和严格 Clippy 通过，122 个可执行单元测试通过；GUI 端到端、真实多显示器、HiDPI 和跨平台探针仍缺失，2 个真实桌面测试被忽略。
- 触发条件：继续以“静态检查和单元测试通过”作为生产完成标准。
- 失败模式：平台运行时、窗口交互、权限对话和显示缩放回归进入主分支。
- 缓解措施和必需验证：保持 fmt/Clippy/单元测试为合并门禁；补充 fake 服务契约、无显示环境启动、真实桌面探针和关键操作场景后，才评估可发布基线。
- 回滚或隔离动作：新实验代码必须在 feature/实验模块中隔离；无法自动化的真实桌面路径不得宣称已经验证。
- 负责人和状态：未分配；静态门禁已缓解，发布验证开放。

## R-009：后台任务与 UI 生命周期仍未完全收敛（中）

- 证据和影响范围：2026-08-01 OCR 适配器已从外部 `kill -9` 和无归属等待线程迁为自身 `Child` 的取消、超时、输出上限和 `wait` 回收；`OcrJobService` 与 `ExportJobService` 均已接入 `desktop_shell`，覆盖贴图/Overlay OCR、PNG 保存、图像与 OCR 文本剪贴板；剪贴板 child 使用拥有式临时文件和有界 stderr。服务保存 worker 句柄，退出先取消并在 2 秒内 join 已收敛 worker，剩余数量会显式输出。
- 触发条件：用户关闭贴图/重截/退出时后台剪贴板、导出或 OCR worker 仍在运行，或文件系统在保存中断时失败。
- 失败模式：Overlay 的 OCR、复制和保存结果现已同时受 owner、选区身份和标注 revision generation 门禁保护，直接剪贴板 child 已由适配器回收，PNG 在 Linux 本地文件系统已原子发布；但忽略取消的 worker 会在有界等待后残留，复杂 OCR/剪贴板后端的子孙进程、退出卡顿和跨平台回收策略仍缺乏真实验证。
- 缓解措施和必需验证：保持剪贴板与导出经受监督任务提交；适配器在协作式取消宽限期后回收自身进程；退出测试必须证明无残留 worker/子进程或如实报告剩余数量；跨平台或断电语义需独立验证，不得从 Linux 文件测试外推。
- 回滚或隔离动作：先保留当前 OCR 服务作为隔离边界；剪贴板/导出迁移失败时关闭对应异步入口，保留同步 fake 接口，完成生命周期契约后重新开放。
- 负责人和状态：未分配；开放。

## 风险一：上下文漂移

- 触发条件：代码、配置或工作流变化后，没有同步更新对应上下文文件。
- 缓解措施：根据变化的事实或生命周期状态更新 `system/`、计划或任务。
- 回滚方式：只回滚上下文变更，不改变源码行为。

## 风险二：遗留迁移丢失

- 触发条件：未做语义分类就机械移动 `prompt.md`、`.memory/` 或 `.prompt/`。
- 缓解措施：先生成迁移清单；所有长期事实和可执行任务完成核对前保留来源文件。
- 回滚方式：从未改动的来源文件恢复，只删除生成的上下文文件。

## 风险三：外部依赖副作用

- 触发条件：校验或测试连接共享数据库、队列、缓存或远程接口。
- 缓解措施：优先离线检查，只运行明确授权的隔离验证。
- 回滚方式：产生副作用前停止，并在当前任务中记录阻塞证据。
